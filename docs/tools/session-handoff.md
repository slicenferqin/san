# session_handoff

> Proactively summarize the current session and push the document to a target `san:*` session (another San runtime on this machine) so work continues there — without switching or changing this session.

Part of the two-layer cross-session capability: `hub` owns discovery, plain messaging, remote control, and transport; `session_handoff` is the dedicated high-level flow where the source session generates its own handoff summary and pushes it to the target session.

## Source
- Entry: `packages/coding-agent/src/tools/session-handoff.ts` (schema, `SessionHandoffTool`, createIf gating)
- Model-facing prompt: `packages/coding-agent/src/prompts/tools/session-handoff.md`
- Session generator: `ToolSession.generateSessionHandoff(focus?, signal?)` — implemented by the root `AgentSession` (`generateHandoffDocument`); `packages/coding-agent/src/session/agent-session.ts`
- Transport: `packages/coding-agent/src/peer/` — `CrossSessionClient.send({ to, body, kind: "handoff" })`, `PeerSendWire.kind`, broker pass-through
- Discovery base: `packages/coding-agent/src/tools/hub/` — `hub op:"list"` returns the exact `san:<12 hex>` ids this tool accepts

## Inputs

| Field | Type | Required | Description |
|---|---|---|---|
| `to` | `string` | Yes | Exact target session id from `hub op:"list"` — the precise `san:<12 lowercase hex>` id of another runtime. Anything else is rejected. |
| `focus` | `string` | No | Optional focus steering what the generated handoff summary emphasizes. |

There is deliberately no body/message parameter: callers can never pass a hand-written summary.

## Outputs
- Success:
  - `content[0].text = "Handoff delivered to <target> (<outcome>)."`
  - `details = { to, outcome }` where `outcome` is the transport receipt (`injected` / `woken`).
- Failure:
  - `isError: true`, `details = { to, outcome: "failed" }` (precondition/validation errors) or `details = { to, outcome: "failed", error }` (delivery failures), and the text names the reason.

## Flow
1. `SessionHandoffTool.createIf(...)` exposes the tool only in root sessions (`taskDepth === 0`); subagents never see it in their schema.
2. `execute(...)` validates, in order:
   - a live `session.crossSessionClient` (transport present), else an error result;
   - a live `session.generateSessionHandoff` (generator present), else an error result;
   - `to` matches exactly `/^san:[0-9a-f]{12}$/` and is not this runtime's own id (`crossSessionClient.id`), else an error result.
3. The summary is generated by `session.generateSessionHandoff(focus, signal)` — the abort signal and focus are forwarded verbatim. Empty/`undefined` summaries, and generator throws, become error results.
4. The document is sent as `{ to, body: document, kind: "handoff" }` through the existing peer transport. The source session is not switched or changed; delivery is fire-and-forget with an immediate receipt.

## Modes / Variants
- Focused handoff: pass `focus` to steer what the generated document emphasizes.
- The transport's `kind: "handoff"` marker lets the receiving runtime distinguish a handoff document from ordinary hub messages (receiver-side injection is owned by the session layer).

## Side Effects
- Network: one peer-transport message to the target runtime on this machine.
- Session state: none — the source session is untouched (no switch, no fork). Generation runs the same ephemeral-turn pipeline as the local `/handoff` flow.

## Limits & Caps
- Root sessions only (`taskDepth === 0`); subagents get no tool at all.
- The body is still bounded by the transport's `MAX_PEERS_MESSAGE_BODY_BYTES` (64 KiB UTF-8). Oversized summaries fail with an error result — the tool never silently truncates.
- Targets must be exact `san:<12 lowercase hex>` ids; `hub op:"list"` is the only sanctioned source of ids.

## Errors
- `Cross-session transport is unavailable in this session.` — no live `crossSessionClient` (headless/unregistered roots).
- `Handoff generation is unavailable in this session.` — no `generateSessionHandoff` (session layer not wired).
- `Invalid target "<to>": expected the exact san:<12 lowercase hex> id of another runtime from hub op:"list".` — format or prefix mismatch.
- `Cannot hand off to this session itself.` — `to` equals this runtime's own transport id.
- `Handoff generation produced no summary.` — the generator returned empty/`undefined`.
- Generator errors (e.g. `Nothing to hand off (no messages yet)`, `Handoff cancelled`) are surfaced as error results with the generator's message.
- `Handoff to <to> failed: <reason>` — failed delivery receipt or a transport throw (e.g. body over the 64 KiB cap, broker unreachable); the receipt marks the result `isError: true`.

## Notes
- Two-layer design: `hub` keeps doing discovery (`list`), plain messaging, remote control, and transport; this tool layers the high-level push on top. Follow-ups after the handoff continue through hub messaging.
- The receiving side's handoff injection (turning a `kind: "handoff"` message into a session handoff) is owned by the session layer, not this tool.
