2. 第五轮 Findings → 修复

P0 · planTokenBudget 未覆盖最终 render

每个 candidate 都按最终 audit 渲染，再决定是否丢弃整个 material。

  • fitMaterialsToPlanBudget 接收 buildAudit，在每轮候选选择中渲染同一份 budget、quality gate、coverage 和 audit materials。
  • 最终的 renderedContent 与 tokenEstimate 直接采用已通过 cap 的 candidate，不再先用固定的 outcome: pass 假 audit 拟合、后以真实 audit 重渲染。
  • 仍然只整体丢弃 recall → 最旧 digest → checkpoint；不做字符截断。若连空 shell 都超过极端 cap，继续保留无 coverage 的完整 shell，避免删 raw 后没有完整 replacement。

主文件：packages/coding-agent/src/context-steady/planner.ts

合同：fits the final quality-gated ContextPlan wire content within planMaxTokens

P0 · final plan 没有被重新投影与 re-gate

新增 provider-boundary 的固定点构建。

  • #buildContextSteadyPlanForProvider 先构建无 projected audit 的 plan，再估算 materialized provider input，并带该数值重建。
  • 每次最终 render 都重新估算；只有 finalProjection === projectedInputTokens 时才接受。这样 audit 既不会低估真实 wire，也不会因初始估算偏高而错误 hard-pressure。
  • 最多四次重建仍未收敛时，以 Number.MAX_SAFE_INTEGER 建立 hard-pressure plan，调用方拒绝 provider call，避免带着未验证边界发请求。
  • 首次请求与 full tool-loop re-gate 均复用此路径；tool-loop 的既有 full-context 去重计量保持有效。

主文件：packages/coding-agent/src/session/agent-session.ts

合同：m2 keeps the emitted quality-gated ContextPlan within its configured wire budget，加上既有 true-overflow / legal-tail tool-loop tests。

P1 · config-cli sequential suite failure

隔离 test project scope，而不是改变全局与项目配置的正确优先级。

  • 失败测试将 agent dir 指向临时目录，但保留了仓库 project root；.san/config.yml 的 modelRoles 因项目优先级覆盖其临时全局写入。
  • config-cli.test.ts 现在在 beforeEach 同时将 project root 指到临时目录，并在 afterEach 恢复原路径。
  • 这恢复测试所宣称的合同：CLI 在没有 project overlay 时 set 后 get 返回刚设置的 record；不影响真实项目 overlay 行为。

文件：packages/coding-agent/test/config-cli.test.ts
