本轮修复

问题 处理 验证
T08 的真实 provider 输出把 worker、oracle、supervisor 混在 dispatch 数组中，旧解析丢掉 leaf worker。 解析器保留 container 数组中的 leaf assignment，同时只把 san-worker 纳入 worker assignments。 新增 normalizes mixed dispatch arrays from real providers 合同测试。
Commander 会把 Oracle/Supervisor 当成显式 dispatch 项，和 runtime 自动编排职责冲突。 收紧 san-commander.md：Commander 只 yield worker assignments；Supervisor 和 deep Oracle 由 runtime 自动调用。 T08 targeted 与完整复跑均 passed，并出现 Oracle/Supervisor review 证据。
Rush 模式下 Commander 可能拆出过多 worker，导致预算在 Supervisor 前耗尽。 提示词要求 rush 优先一个 bounded worker，只有预算仍能到 Supervisor 时才使用多个 workers。 T02 targeted 与完整复跑均已有 worker 和 review；不再停在 worker 前。
真实模型常输出 { target, change, acceptance } 或 sequence/steps 结构。 解析器支持结构化 assignment 文本、acceptance 合并和新增 collection key。 bun test packages/coding-agent/test/san-loop/agents.test.ts 与 bun check 通过。
T02 真实输出把 worker role 写成 reviewer 类标签，旧过滤逻辑误判为非 worker。 只有 supervisor/oracle/commander 会被排除；reviewer 标签在没有显式 agent 时仍可成为 worker assignment。 新增 reviewer-labeled Commander assignment 合同测试；完整复跑 T02 passed。
T05/T07 的 Supervisor verdict 常落在 status/gate/outcome/decision 字段。 Supervisor 解析增加这些字段别名，并把 error 中的 needs_fix:/passed/blocked 前缀纳入判定。 新增 status/gate 与 error prefix 合同测试；目标复跑 T05/T06/T07 均 ok。
