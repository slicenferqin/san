2. 对第三轮 Findings 的逐项回应

P0 · Tool loop 绕过 320K

每次 provider call 重新 gate，不再只在用户请求开始时 gate 一次。

  • #transformContextForProvider 调用 #refreshContextSteadyPlanForProviderCall。
  • 仍在 control band 内：冻结历史材料，仅 re-materialize。
  • 跨 control / 逼近 burst：基于 live branch + tool tail 重建 plan；超 burst 写 hard_pressure audit 并拒绝后续 provider call。
  • 新增设置 san.contextSteady.burstWindowTokens（默认 320000）。

主文件： packages/coding-agent/src/session/agent-session.ts、settings-schema.ts

合同测试： agent-session-m2.test.ts「re-gates tool-loop provider calls…」

P0 · Checkpoint 跨分支污染

Checkpoint 只消费当前 branch。

  • #maybeAppendContextSteadyCheckpoint 从 getEntries() 改为 getBranch()。
  • 与 planner / materialize 的 branch 口径一致。

主文件： agent-session.ts

合同测试： agent-session-m2.test.ts「builds checkpoints only from the active branch」

P0 · Fallback 经 checkpoint 获得删除权

Fallback digest 永远不能通过 checkpoint 间接覆盖 raw 原文。

  • checkpoint.ts：合成 coveredSourceEntryRefs 时跳过 fallback === true。
  • source-index.ts：展开 v2 covered refs 时剥离 fallback span（防旧/坏写入回流）。
  • Planner 原有「fallback material reference-only」规则保持不变。

主文件： checkpoint.ts、source-index.ts、planner.ts

合同测试： source-index / planner「fallback never gains coverage via checkpoint」

P1 · Hard pressure 不可审计 / 当前 prompt 丢失

拒绝前先落 journal prompt + plan audit。

  • hard_pressure 路径：先 append 用户 prompt，remap pending refs，append san.context_plan，再 throw。
  • 同时置位 #contextSteadyPendingBudgetPressureRebase，后续可走 budget_pressure rebase 语义。

合同测试： agent-session-m2.test.ts「persists hard-pressure audit and the refused prompt」

P1 · pre-prompt compaction / idle status 不共享 plan

Plan 建立提前；idle 保留 last plan snapshot。

  • 请求生命周期内：先 build plan，再 pre-prompt compaction。
  • #contextSteadyLastPlan 在 turn end 后仍供 #estimateStoredContextTokens / getContextBreakdown 使用。
  • Provider send 仍优先 #contextSteadyRequestPlan。
P1 · Semantic required + topic shift

生产 required set 不再只有「最近 3 轮」。

  • #contextSteadySemanticRequiredEntryRefs：最近 exact turns + 带 openQuestions/risks/filesTouched 的 digest span。
  • Planner 在显式 topic shift 时退场无关 checkpoint/digest，并写 rebaseReason: "topic_shift"。
  • AgentSession 对 topic/resume/budget 边界会 rotate provider session（safe rebase）。

合同测试： planner topic-shift；dogfood「records topic_shift rebase…」

P1 · plan maxTokens / qualityWindowTokens=0

cap 作用在最终 rendered wire；0 语义统一为默认 240K。

  • Planner 先按 material budget 选择，再 fitMaterialsToPlanBudget，最后 clampRenderedPlanToBudget 硬裁 wire。
  • Schema 文案与 budget 实现对齐：qualityWindowTokens=0 → 240K steady default。
  • 新增 burstWindowTokens schema。
P1 · pending_* audit refs

审计在 journal append 后 remap，再单次持久化。

  • 请求开始不写 audit（hard_pressure 除外）。
  • turn 结束后 remap pending_* → 真实 entry id，再 append 一次 plan audit。
  • Digest span 端点会跳过 plan custom entry，避免 toEntryId 污染。
P1 · 推荐 overlay 测试

settings-manager 对齐 recommended YAML。

  • qualityWindowTokens: 240000
  • contextPlan.* 键（不再断言旧 contextPacket.*）
P2 · R3/R5/R6 收口
  • Epoch / rebase： epochId 编码 reason + rebase boundary；resume / budget_pressure / topic_shift 可触发 safe rebase。
  • Checkpoint hard trim： 按 nextSteps→risks→files→decisions→intents 裁减，并在极端 budget 下 clamp 文本。
  • Legacy： package export 明确 packet/prune 为 legacy-compat；active AgentSession 不调用。
  • Digest transport： LLM digest 走 session prepareSimpleStreamOptions，带 sanSideRequest metadata 与隔离 sessionId。
  • Dogfood： 新增真实 AgentSession 多轮 + tool loop 探针；保留纯模拟 dogfood。

4. 运行时行为变化（reviewer 关注点）

Before

只保护第一次 provider call

tool result 膨胀后仍 materialize 旧 plan；checkpoint 可吃全树；fallback 经 checkpoint 后 raw 可被删；hard pressure 无 audit。

After

完整 request lifecycle 合同

每次 provider call 可 re-gate；checkpoint 仅 active branch；fallback 永不获 coverage；hard pressure 可审计；send/status/compaction 共享 plan snapshot。

user prompt
  → build ContextPlan (preflight, quality gate)
  → pre-prompt compaction (uses plan estimate)
  → provider call #1 materialize(plan)
  → tool result / live tail
  → provider call #N: re-estimate → keep or rebuild plan → hard_pressure abort if over burst
  → settle: TurnDigest (message endpoint only)
  → persist remapped ContextPlan audit
  → maybe checkpoint (branch-only, non-fallback coverage)
  → idle status uses last plan snapshot
