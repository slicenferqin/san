San v0.3 · P0 Design Freeze · 2026-07-10

先冻结控制面，再允许经历改变行为

本文是 San v0.3 Brain Runtime 的规范性实现合同。它冻结命名、scope identity、生命周期、状态权威、投影、撤销、Prompt authority 和实施顺序；M1 及后续 issue 必须以本文为准。

冻结结论

P0 采用 review-first 架构。 M1-M3 只建立可审计候选、决策、materialized state、解释与撤销能力，不改变 agent 行为。M4 才允许受限 activation；M5 才允许向 memory、managed skill、check 等外部系统投影。
权威源Session JSONL 中不可变 Candidate / Decision entries 是审计权威；SQLite 是可重建 materialized view。
行为变化Candidate 永远只是建议。只有 Decision 可改变 active state；外部 projection 不能反向成为事实源。
控制面先行Explain、audit、approve/discard、undo 必须早于 auto-apply、skill 写入和长期 memory 写入。

Scope Identity

KindscopeKey迁移与隔离语义
useruser:local，由当前 agentDir 隔离。不写用户名、home 路径或邮箱；不同 agentDir 不共享。
repo规范化 primary remote + git common-dir identity 的稳定 hash。fork 因 remote 不同而隔离；没有 remote 时使用持久化生成的 repo UUID。
projectrepoKey + worktree identity；非 Git 项目使用持久化 project UUID。不同 worktree 隔离；symlink 先 realpath；目录移动通过 identity alias 迁移，不按 basename 猜测。
sessionsession ID。永不跨 session 激活；resume 保持同一 key。
  • Scope resolver 必须返回 kind + key + resolverVersion。
  • 未知、歧义或迁移失败时降级到更窄 scope，禁止扩大。
  • 同名目录、fork、worktree、symlink 必须有定向测试。

Digest → Capture 生命周期

Capture 必须链接到真实 #generateTurnDigest() Promise。 不新增独立、竞态的 agent_end listener；由同一个 #trackPostPromptTask() 跟踪 digest 持久化和 deterministic capture。 
const digestAndCaptureTask = this.#generateTurnDigest(turn)
  .then(digestResult => brain.captureTurn({ turn, digestResult }))
  .catch(error => brain.recordCaptureError(turn, error));

this.#trackPostPromptTask(digestAndCaptureTask);
场景冻结行为
Digest 已持久化Capture 使用 digest entry ref；同一 evidence 由 idempotency key 去重。
Digest 跳过Capture 可使用当前 turn message-span deterministic fallback，并记录 source mode。
Digest 失败记录 san.brain.error；fallback capture 仍可运行，不阻断 turn。
下一真实用户 prompt 很快到达M2 起最多等待 pending capture 150ms；超时则本轮跳过新 state，下一轮再生效。禁止无限等待。
synthetic continuation不等待、不激活新 Brain state，避免维护轮次改变用户可见行为。
session stop / dispose有限等待 tracked task；未完成项保持 ledger 可重放，启动时 reconcile。

状态权威与投影协议

  1. Evidence：原始 session entries、TurnDigest、accepted San Loop attempt、工具/文件 refs。
  2. Candidate Ledger：append-only 建议；不改变行为。
  3. Decision Ledger：append-only、不可变、幂等；是行为变化的审计权威。
  4. SQLite Active Store：由 Decision 重放得到的 materialized view；允许删除重建。
  5. Outbox：与 active state 同一 SQLite 事务写入 projection intent。
  6. External Projection：memory、managed skill、check suggestion；失败可重试、可补偿。
Projection 状态含义
pendingDecision 已生效，外部写入尚未开始。
applying有 lease 的执行者正在写入；超时可被 reconcile。
applied外部 revision/hash 已记录。
failed记录具体错误和有限重试次数；active state 不回滚。
compensatingUndo 正在回滚该 Decision 拥有的 revision。
compensated该投影已安全撤销。
blocked检测到人工修改、CAS 冲突或能力缺失，需要人工处理。
Undo 是新 Decision，不是删除历史。 只补偿目标 decision 创建且 revision/hash 仍匹配的投影。后续人工或其他进程已修改时标记 blocked，禁止覆盖。

SQLite 与迁移

  • 数据库：~/.san/agent/brain/brain.sqlite。
  • 启用 WAL、busy_timeout、foreign keys。
  • 数据库结构只使用 PRAGMA user_version 做原子迁移。
  • JSONL payload 保留 schemaVersion；future version 只展示，不投影、不激活。
  • Decision apply、active revision、outbox insert 必须在同一 SQLite 事务。
  • 启动时按 Decision idempotency key reconcile；不得扫描全文生成新判断。

Prompt Authority 与安全渲染

Authority来源Brain 可否覆盖
最高System/developer 合同、项目规则、工具安全合同永不
高当前真实用户指令永不
高当前 workspace 和真实工具结果永不
中当前任务状态、San Loop 决策和 accepted review只能补充，不能改写证据。
低Brain active state仅建议默认行为；冲突时跳过并写 activation trim reason。
最低ContextPacket、memory recall、历史文本作为不可信历史数据。
  • Brain renderer 只渲染 typed fields；禁止拼接候选原文为指令。
  • 所有文本 JSON-escape；移除控制字符；限制单项和总长度。
  • 历史中的 XML、Markdown fence、命令和工具语法不得升级 authority。
  • M4 建立统一 injection planner，真实裁剪 Brain + ContextPacket + San Loop 总预算。
  • Activation audit 记录选中规则、scope match、role、token allocation、trim reason 和 rendered hash。

Legacy Memory 迁移

模式行为
Brain disabled保持现有 memory backend 与 autoRetain 行为，避免破坏已有用户配置。
Brain review-onlydogfood overlay 必须显式关闭 Mnemopi/Hindsight legacy autoRetain；显式 /memory save 仍可用。
Brain projection enabled长期自动写入只能来自 san.brain.projection outbox。
发现 legacy autoRetain=true启动时显示具体迁移告警；默认进入 compatibility mode，不静默修改用户文件。

Managed Skill Draft 与回滚

  • 候选和草案先存 Brain store；不得直接写 active managed-skills。
  • 批准后写入 active skill，并记录 decisionId、revision、before/after hash。
  • Create 必须确认 owner；Update 必须 CAS 匹配上一 revision/hash。
  • Undo 只删除或恢复自己创建的 revision。
  • 文件已被人工或其他进程修改时 projection 标记 blocked。
  • v0.3 不自动创建 hook 或改变工具权限。

Conflict 与 Supersede

Key语义
claimKey同一命题槽位：scope + type + subject + predicate。
dedupeKey同一值：claimKey + normalized value。
conflictKey会产生互斥行为的候选集合。

相同 dedupeKey 合并独立证据；相同 claimKey、不同 value 形成 conflict。批准新值必须生成 supersede Decision，旧值不通过“增加证据”继续增强。

Crash / Failure Matrix

断点恢复规则用户可见结果
Candidate append 成功，SQLite 未索引启动 reconcile 按 candidateId 补投影。候选稍后出现在 inbox；不重复。
Decision append 成功，SQLite transaction 未完成按 idempotencyKey 重放 Decision。状态最终一致；不丢审计。
SQLite active state 成功，outbox 未执行pending outbox 后台/显式命令重试。Brain state可解释；外部能力暂未落地。
Memory save 成功，回执丢失使用 projection idempotency key 查询或安全重试；backend 无幂等能力时标记 blocked。禁止盲目重复写。
Skill 写入成功，activation audit 未写通过 decisionId/revision/hash reconcile 并补 audit。技能不重复创建。
Undo 时 skill 已人工修改CAS 失败，projection blocked。保留人工修改并报告冲突。
两个进程同时 approve唯一 idempotencyKey + revision CAS；一个成功，一个读取已应用状态。一个 active revision。
Capture 超时不阻断下一 prompt；候选延迟到下一轮可见。当前任务继续。
Future schemaVersion只读展示 unsupported；不迁移、不激活。安全降级。

冻结实施顺序

阶段内容行为变化
P0本文合同、文档收敛、失败矩阵。无。
M1Candidate/Decision ledger、SQLite materialized store、migration、只读 /brain inbox|profile|explain。无。
