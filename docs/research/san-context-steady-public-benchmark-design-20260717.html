San Context Steady 公共 Benchmark 设计

目标不是展示一条漂亮会话，而是提供可复现、可审计、质量门控的 A/B 实验，证明 San 能在数百次工具调用和超长任务中控制活跃上下文，同时减少 token 与实际费用，并保持交付质量。

稳得住原始 journal 持续增长时，活跃 Prompt 保持在稳定区间，长 turn 不因分段预算饿死。
省得下与原生压缩基线使用同模型、同任务、同配置，比较真实 provider usage 和账单口径。
活干对只有通过隐藏测试、约束检查和产物审核的运行才进入效率比较。

1. 核心实验

每个任务使用两个真实运行模式，顺序随机化。旁路虚拟基线仅用于解释机制，不作为对外节省结论。

参考模型冻结

正式参考运行的 Native 与 Steady 主请求都使用 asxs/gpt-5.6-sol:xhigh，Steady 的 TurnDigest 使用 self/gpt-5.4-mini。两种模式使用独立 runtime key，且各自的 asxs 与 self 请求都归入同一模式凭证；密钥不进入模型配置或实验产物。Native 与 Steady 禁止自动切换服务商；429、5xx、网络或并发故障会使整个配对失效，并最多把两种模式共同重跑一次。

L1-L4 是自然编码任务，不惩罚更少的工具调用；L5 是明确标注的 Controlled Stress。其 benchmark_step 后一步必须提交前一步 proof，不能批量领取，每个证据分片都进入最终 evidence.ndjson 与事故分析产物。

3. 质量评分

质量采用分层门禁，LLM judge 只处理无法机械判断的部分，不拥有最终否决机械事实的权力。

  1. 硬门禁：构建、测试、隐藏测试、安全约束、任务要求必须全部通过。
  2. 约束保持：在任务早期埋入可验证约束，最终检查是否遗忘、反转或重复询问。
  3. 产物质量：最小改动、错误处理、文档一致性和无无关修改，使用固定 rubric 双盲审核。
  4. 任务完整性：不得以“预算不足”“先做到这里”作为成功；必须到达明确 terminal outcome。

Primary quality metric: pass rate 与 quality score 的非劣性。Steady 只有在质量不低于 Native 的情况下才能宣称节省。

5. 统计与运行规模

档位任务 × 模式 × 重复总运行数用途
Smoke（默认）1 × 2 × 12验证 runner、凭证、artifact 和 verifier，不形成产品结论
Standard3 × 2 × 16开发期方向检查，不对外宣称统计显著
Confidence3 × 2 × 318候选版本对比和内部决策
Release5 × 2 × 330公开发布证据；必须显式确认高成本运行
Extended5 × 2 × 550方差过大或论文级扩展证据；不是默认发布门槛
  • 普通执行默认只跑 2 次；Release 默认 30 次，只有方差不足以支持结论时才扩展到 50 次。
  • Release / Extended 必须先执行费用预估，并通过显式高成本开关才能启动；预估包含一次整对基础设施重跑的上界。
  • Native / Steady 在每个任务内随机交错，避免时间段、服务负载和缓存热度偏差。
  • 报告中同时展示每次运行，不只展示均值；主统计使用配对中位数、IQR 和 bootstrap 95% CI。
  • 预先冻结失败排除规则。Provider 5xx、限流和本地基础设施故障单独标记，但不得静默删除。
  • 至少发布一次完整失败案例，避免只展示成功样本。

6. 防作弊与可复现要求

  • 任务描述公开，隐藏 verifier 在运行结束后公开；开发期间不得让 Agent 读取 verifier。
  • 两种模式使用同一模型版本、provider、thinking effort、工具定义和 system prompt。
  • 每次运行使用全新工作区、会话目录和 prompt cache key，禁止跨运行复用缓存。
  • 记录 Git commit、模型标识、context window、配置文件 hash、任务 fixture hash、开始结束时间和价格表。
  • 原始 session、context probe、stdout/stderr、最终 diff、测试日志和汇总 JSON 全部作为 artifact 发布。
  • 报告生成器只读取 artifact，不允许手工填写核心数字。

  --task-file packages/coding-agent/examples/context-steady-benchmark-smoke-tasks.json \

该命令不调用模型，只输出配对数、代码/config/任务 hash 和包含一次整对重跑的费用上界。付费运行通过 --runtime-keys-stdin 读取 Native/Steady 凭证，禁止将密钥放入 runner 启动环境；实际 Smoke 仅运行 Native 与 Steady 各一次，Release / Extended 还必须显式传入 --allow-expensive。

8. 对外声明门槛

声明最低证据
“能稳住长任务”L1/L5 raw journal 超过原生阈值，Steady P95 active context 保持在控制带内，任务完成且无预算饿死。
“节省 tokens / 成本”质量非劣前提下，真实配对运行的 prompt tokens、实际费用和 cost/pass 均下降，并给出置信区间。
“质量没有下降”隐藏测试 pass rate 非劣，约束保持检查通过，公开失败样本和评分 rubric。
“社区可复现”一条命令运行、公开 fixture/verifier/config、机器可读 artifact 和自动生成报告。

9. 当前真实会话的定位

会话 019f6a4f-6a05-7000-b199-0914f1549de1 是 pilot evidence，不作为最终 A/B headline。它已经证明 benchmark 的压力规模可达成：

  • 332 次模型事件、10 次 Segment / Compaction。
  • raw journal 569,916 tokens，最终 active context 49,604 tokens。
  • 稳定前缀缓存读取率 93.7%。
  • 真实成本约 $26.87；缓存相对完全未缓存节省约 $94.94。

正式报告不能把“完全未缓存”冒充 Native，也不能把 raw-active 累计差直接当作节省；必须等待真实 Native 配对结果。

10. 实施边界

Runner、成本保护、随机配对、隔离 Git 工作区、主请求与维护请求 usage 汇总、顺序证据工具、5 个任务 fixture、隐藏 verifier、JSON/HTML artifact 已实现。正式任务入口为 packages/coding-agent/examples/context-steady-benchmark-tasks.json。2026-07-17 的首轮 xhigh Smoke 因隔离 Settings 未暴露给旧全局代理，导致 Steady 的 Edit / Write 工具异常，该轮已作废；修复后的 Smoke 只验证了凭证隔离、主模型、Digest 模型、probe、artifact 和 runner，不形成效率结论。随后完成的 30-run Release 在审计中发现 L5 可经 eval 间接批量调用 benchmark_step，没有满足预注册的逐模型回合压力契约；该轮数据只保留作诊断，不得用于 Context Steady 节省声明。Runner 现已改为严格工具白名单并关闭此旁路，下一轮正式证据必须基于修复后的 source hash 重新生成。

完成定义：社区成员只需要准备一个兼容模型配置并执行一条命令，即可得到 Native / Steady 的完整配对 artifact、质量结论、token 曲线和 HTML 报告；任何 headline 数字都能回溯到具体 session 行。
