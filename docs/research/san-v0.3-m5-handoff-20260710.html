6. 继续开发的入口

短期目标

  • 从 M5 之后继续推进 v0.3，下一个自然方向是把投影执行从“能力已具备”推进到“dogfood 安全可观测”。
  • 保持 Brain capture / activation / projection 默认关闭；任何 dogfood 都通过显式配置启用。
  • 继续沿用 JSONL 为权威源、SQLite 为可重建物化视图的原则。
  • 保持 undo 的边界：只撤销当前生效 approve；存在后续 revision 时明确拒绝。

优先检查点

  1. 确认 M5 的 projection audit 在真实 session 中能被 debug / explain 清楚呈现。
  2. 设计 M6 前先读 docs/research/san-v0.3-brain-technical-implementation-20260708.html 和 docs/research/san-v0.3-p0-design-freeze-20260710.html。
  3. 如果要开 dogfood，先写最小配置 overlay，不要直接改默认值。
  4. 新增任何外部投影目标时，必须先定义 typed draft 和 CAS / compensation 策略。

7. 风险与注意事项

风险处理方式
.san/mcp.json 未跟踪这是本地配置。切换机器时手动处理，不要默认提交。
Projection 会写外部系统当前默认关闭。任何真实写入必须要求 san.brain.projections.enabled=true，并保留 audit。
Managed Skill 写入只允许写 ~/.san/agent/managed-skills，不能碰用户手写 skills；继续保持 symlink 拒绝和 CAS。
legacy autoRetain不要自动修改用户配置；只计算有效值并提示 warn / block。
规则中断之前触发过 inline cast 读取属性规则。后续处理 unknown shape 时用 schema 或 type guard，不要写 (value as { field: unknown }).field。
