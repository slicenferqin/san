SAN CONTEXT STEADY / 240K CONTEXTPLAN
决策证据合同架构接入阶段测试验收
重写版 · 技术实施方案 · 2026-07-12

用单一 ContextPlan，替换 packet + prune 双引擎。

这份方案重新定义 Context Steady 的实施边界：完整 journal 继续作为事实源，provider 每轮只看到由 planner 选择出的高质量工作投影。240K 是稳态目标，不是删除任务证据的硬刀；当质量要求超过控制带时，系统进入有审计的 burst，而不是静默遗忘。

Implementation invariant

一轮只做一次选择。

provider payload、状态栏、compaction、debug report 和 audit 必须消费同一个 ContextPlan。任何第二套裁剪逻辑都是 drift 风险。

01 / Decision

不要继续修补 v0.1；重写 provider 投影层。

当前 v0.1 已有可保留资产：TurnDigest、entryId 证据、fallback 修复、checkpoint 聚合和部分 packet 裁剪经验。但 active runtime 的核心方向错误：它同时让 digest 授权删除原文，又让 packet delta 无限累积。重构应保留资产，替换决策层。

Retire

ContextPacket active engine

不再把动态摘要作为 custom developer prelude 注入。旧 san.context_packet 仅兼容读取，不再新写入 active provider context。

Retire

all-digest prune

不再扫描所有 TurnDigest 推断可删 entry。只有当前 plan 的显式 coverage 可以让原文退出 provider payload。

Introduce

ContextPlan

planner 生成唯一选择结果：材料、表示方式、coverage、预算、质量结论、epoch 与 rebase 原因。

Preserve

Full journal

SessionEntry journal 保留完整事实。Context Steady 只改变 provider working set，不删除用户历史，不迁移旧 JSONL。

实施口径：本计划不是产品提案二次讨论，而是把已确认的质量优先架构落到代码、测试和切换顺序。若代码实现与本合同冲突，以本合同为准。

03 / Non-negotiable contracts

十条合同决定实现能否合入。

C-01

Journal 是事实源。ContextPlan 不能删除、改写或覆盖原始 SessionEntry。

C-02

240K 统计 provider 全输入。预算包含 system prompt、tool schemas、provider overhead 与 messages。

C-03

质量优先。当前 prompt、验收标准、未解决错误、当前文件和活跃工具对不能为回到 240K 被删。

C-04

每个 settled source 恰好一种可见表示。exact、evidence stub、digest、checkpoint、omitted 互斥且可审计。

C-05

Omitted 必须有 coverage。没有替代物的原文只能 exact 保留。

C-06

工具对原子。当前 assistant tool call 与 tool result 不可拆；旧大结果只在可回读时 stub。

C-07

一个 plan 驱动所有消费者。provider、状态、compaction、debug 不得重新各自 prune。

C-08

动态数据低权限。digest、checkpoint、recall、stub 都是数据，不是 developer/system 指令。

C-09

Rebase 低频且可解释。只在用户边界或 settled 安全点执行；tool loop 内不重排旧历史。

C-10

Disabled parity。san.contextSteady.enabled=false 时不写 plan、不变消息、不 reset cache。

04 / Target architecture

Journal → SourceIndex → ContextPlan → Materializer。

ContextPlan 是选择记录，不是摘要文本。Materializer 只渲染 plan，不再做第二次重要性判断。

01 / truth

Session Journal

完整 messages、custom entries、branch、attachments、tool results、旧 packet / checkpoint。

02 / index

SourceIndex

turn bundles、entry refs、tool pairs、file evidence、digest refs、checkpoint refs、ephemeral recall。

03 / decision

ContextPlan

材料选择、representation、coverage、budget、quality gate、epoch、rebase。

04 / projection

Materializer

生成 provider messages；派生数据低权限；当前 live tail 完整保留。

05 / consumers

Shared snapshot

provider send、status、compaction、/context plan、audit 共用同一 plan id。

05 / Budget model

预算是完整输入工作台，不是 packet cap。

统一公式

configuredSteady = positive(qualityWindowTokens) ? value : 240000
reserve = max(32000, floor(model.contextWindow * reserveRatio))
hardInputCeiling = max(0, model.contextWindow - reserve)
steadyTarget = min(configuredSteady, hardInputCeiling)
configuredBurst = positive(burstWindowTokens) ? value : 320000
burstCeiling = min(max(configuredBurst, steadyTarget), hardInputCeiling)
controlMax = min(burstCeiling, floor(steadyTarget * 13 / 12))
messageBudget = selectedInputLimit - nonMessageTokens

区间语义

  • 0–200K：舒适区，不为填满目标追加无关历史。
  • 200K–260K：常态控制带，优先保持稳定 prefix 与清晰工作集。
  • 260K–320K：质量 burst，必须记录 protected materials 与恢复点。
  • 320K+：hard pressure，尝试 safe rebase、evidence stub、compaction 或模型升级；仍不静默删任务证据。

07 / Planner algorithm

先保护任务，再回收噪声，最后才 rebase。

Step 1

Build source index

识别 turn bundle、tool pair、entryId、附件、文件证据、digest/checkpoint、live extension messages 和 recall。

Step 2

Select required materials

当前 prompt、未完成 turn、活跃工具对、验收条件、最近 exact turns、当前文件和错误证据先进入 protected set。

Step 3

Assign representation

每个 settled source 选择 exact、evidence stub、digest、checkpoint 或 omitted；omitted 必须写 coverage refs。

Step 4

Estimate full input

合并 non-message tokens 和 materialized messages 估算，不只统计 context-steady 生成的部分。

Step 5

Recover safe noise

超过 controlMax 时，先降低分 recall、重复 payload、旧 checkpoint 覆盖 digest；不可删 protected set。

Step 6

Gate quality

若规格、错误、工具因果、文件证据或验收条件缺失，恢复材料并进入 burst_required。

Step 7

Handle hard pressure

超过 burst ceiling 时只在安全边界尝试 rebase、stub、compaction 或 model promotion；仍失败则显式暂停。

Step 8

Freeze snapshot

同一 request 的旧历史选择冻结；tool loop 只追加 live tail，不重新洗牌旧上下文。

08 / AgentSession integration

只在五个安全点接入。

A / user boundary

Create request state

用户 prompt 进入 loop 前建立 ContextSteadyRequestState：requestId、promptGeneration、epochId、recall candidates、rebase reason、plan snapshot。此处停止调用 #buildContextSteadyPacketPrelude。

B / pre-flight

Build preflight plan

文件 mention、附件、prepend messages 和当前 prompt 准备后，以 [...this.messages, ...pendingMessages] 建 source snapshot。pre-prompt compaction 读取 plan estimate。

C / provider send

Materialize final plan

#transformProviderContext 保留 extension transform 后，从 request state materialize final messages；开启 steady 时不再调用 buildContextSteadyPrunedMessages。

D / tool loop

Append live tail

同一 request 多次 provider 调用共享 epoch 和旧历史选择；新 tool call/result 成对追加；不做 topic shift 或 rebase。

E / agent end

Persist digest/checkpoint/plan

settled 后生成净化 TurnDigest，必要时写 checkpoint v2，append plan audit；只有 safe rebase 才 reset append-only cursor 和 provider session。

09 / Security and trust boundary

摘要是数据处理，不是第二个高权限 agent。

Digest side request

  • 输入是白名单结构：user intent、tool status、path、entryId、短摘、error class、可回读引用。
  • 文件正文、大工具输出、二进制文本化内容默认不进入 digest payload。
  • 先经过 SecretObfuscator 和 session side-request preparation，再发送到 digest model。
  • 持久化 digest 保留 placeholder，不做 deobfuscation。

Provider roles

  • 静态处理规则可以在受控 prompt 文件中声明。
  • checkpoint、digest、recall、evidence stub 以 user/data 语义进入 provider。
  • 派生文本携带 provenance 与 trust label，不能成为 system/developer。
  • 外部文本中的指令只作为引用数据，不改变当前任务规则。
10 / Compatibility

向前写新格式，向后读旧记录。

Checkpoint

v1/v2 双读，v2 单写

v2 增加 epochId、covered source refs、previous checkpoint ref 与 rebase reason。只 materialize 最新 checkpoint。

TurnDigest

v1 继续可用

Brain capture/recall 合同不破坏；可增补 metadata，但不能要求旧 digest 迁移。

Old packet

只读留档

resume 时过滤旧 injected packet；/context packet 可作为 legacy report，不再参与 active plan。

Commands

新增 /context plan

展示 budget、materials、coverage、quality outcome、rebase、audit size 和 raw-payload 检查。

SanLoop

写 plan refs

新增 sourceContextPlanRefs；旧 contextPacketRefs 仅作为 legacy optional input。

Rollback

总开关回退

关闭 san.contextSteady.enabled 即回到 non-steady path；不清理 journal 或 audit。

13 / Acceptance and rollback

代码级完成与产品级验收分开。

代码级完成

  • 所有目标 contract tests 通过。
  • Bun check 通过。
  • 无 active packet/prune runtime。
  • audit 不含 raw 大正文或 secret。
  • send/status/compaction 共用 plan。
  • disabled parity 可证明。

产品级联合验收

  • full-history 与 steady-plan A/B 对比质量不下降。
  • 真实 20-turn 任务 p95 常态不高于 260K。
  • burst 不高于 320K 且有原因、持续轮数和恢复。
  • resume 语义等价；无 secret 泄露；复杂实现和排障质量不下降。

Rollback 条件

  • 任务规格、工具因果、秘密边界、resume 语义或 cache 生命周期任一合同失败。
  • 立即关闭 san.contextSteady.enabled。
  • 保留 audit 与 journal 定位，不清理用户历史。
Implementation thesis

完整历史负责不遗忘；ContextPlan 负责当下；240K 负责集中；burst 负责质量。

这次重构的成功标准不是新建一个更聪明的摘要器，而是每次 provider 请求都能回答：看到了什么、为什么看到、哪些原文由什么替代、预算怎么算、何时允许 burst、何时安全 rebase。

JOURNAL IS TRUTH → PLAN ONCE → MATERIALIZE ONCE → MEASURE THE SAME PLAN → BURST FOR QUALITY → REBASE ONLY WHEN SAFE
