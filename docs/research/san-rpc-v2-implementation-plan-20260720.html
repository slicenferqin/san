组件现状目标

事件AgentSessionEvent 原样输出，无 sequenceSessionEvent envelope + eventId + sequence

实施阶段

P1 契约源 NEW

目标：建立 v2 的类型基础和协议骨架，不改变任何运行时行为。

  1. protocol/envelope.ts — ClientRequest、ServerResult、ServerError、Notification 类型
  2. protocol/errors.ts — RpcError 接口、SanErrorCode 枚举（-32001 到 -32070）、error factory
  3. protocol/capabilities.ts — CapabilityDescriptor、CapabilityStatus、ServerCapabilities 常量
  4. protocol/ids.ts — ID 生成（runtimeId、sessionId 已有 Snowflake；新增 leaseId、runId、turnId、eventId、sequence 分配器）
  5. protocol/lifecycle.ts — Session access、Run status、Approval status、Interaction status 状态机与合法转换
  6. dto/session.ts — SessionSummary、SessionSnapshot、RecoveryDescriptor
  7. dto/run.ts — RunSnapshot、QueueItem
  8. dto/approval.ts — ApprovalRequest、ApprovalTarget、PermissionPolicySnapshot
  9. dto/interaction.ts — InteractionRequest union、InteractionResponseParams
  10. dto/context.ts — ContinuitySnapshot、CheckpointSummary
  11. dto/evidence.ts — EvidenceRecord
  12. dto/events.ts — SessionEvent envelope、所有 event data 类型
  13. dto/resources.ts — ContentPart、InputResourceRef、ArtifactRef、ResourceLimits
  14. dto/integration.ts — IntegrationSummary、ExecutionProfile、SessionRuntimeSettings

验收：bun check 通过；类型与需求规范附录一致；无 any、无 ReturnType。

P2 Envelope 层 NEW 依赖 P1

目标：新增 --rpc-protocol=2 入口，完成 JSON-RPC 2.0 帧处理和握手。

  1. rpc-v2-mode.ts — 新入口：stdout purity guard、NDJSON reader、request dispatcher
  2. server.ready notification — 输出 runtimeId、San version、protocol supported
  3. initialize method — 验证 protocolVersion、协商 capabilities、返回 limits
  4. server.getHealth / server.getCapabilities / server.shutdown
  5. Method router — 基于 initialize 状态的访问控制（未握手只允许 3 个方法）
  6. stdout purity — 拦截 process.stdout 非协议写入（复用 PI_NOTIFICATIONS=off 策略 + 额外 guard）
  7. CLI 集成 — launch.ts 增加 --rpc-protocol flag，main.ts 路由到 v2 入口

验收：启动后 stdout 第一行是 server.ready；initialize 往返正确；不兼容版本返回 VERSION_INCOMPATIBLE。

P3 Session 基础 NEW 依赖 P2

目标：暴露 Session index、lease 管理、原子 sync 和事件分页。

  1. session-manager.ts — 封装 listSessions/listAllSessions 为 session.list（分页、搜索、排序）
  2. session.create / session.open — write lease 分配、冲突检测（SESSION_LOCKED）
  3. session.sync — 原子 snapshot/replay + subscription 建立
  4. Event sequencer — 为每个 Session event 分配单调 sequence + eventId
  5. session.events.list — 分页历史事件
  6. session.close / session.recover — lease 释放、interrupted 检测
  7. v1 事件适配层 — AgentSessionEvent → SessionEvent envelope 转换

验收：session.list 返回正确索引；sync 无竞态（并发事件不丢失）；重连 replay 与 snapshot 投影一致。

P4 执行闭环 ADAPT 依赖 P3

目标：Run/Turn/Message/Tool 生命周期通过 v2 事件流输出。

  1. run.start — 接受 prompt、生成 runId、发 run.accepted + run.started
  2. run.steer / run.followUp / run.replace / run.abort
  3. Turn/Message/Tool adapter — 从 AgentSessionEvent 映射到 v2 领域事件
  4. Queue 管理 — QueueItem 快照、queue.item.added/promoted/cancelled 事件
  5. settings.get / settings.update — typed runtime settings
  6. model.list / model.select / thinking.set
  7. execution.profile.list — Solo/Team/Council profile 目录

P5 阻塞交互 ADAPT 依赖 P4

  1. 结构化 Approval — 从 tool approval 系统生成 ApprovalRequest DTO
  2. approval.decide — scope 验证、rule 持久化、fingerprint 生成
  3. approval.rules.list / approval.rules.revoke / approval.policy.get/update
  4. Interaction — 从 ExtensionUI 映射到 typed InteractionRequest
  5. Host Tool — 迁移到 JSON-RPC server request（host.tool.invoke）
  6. Provider auth — auth.login.start + open_url Interaction

P6 资源与集成 NEW 依赖 P4

  1. Resource upload — chunk 分片、hash commit、ContentPart 验证
  2. Host URI resource — resource.registerHostUri
  3. Artifact — artifact.read 有界分块
  4. Integration catalog — Skill/MCP/Extension list/get/setEnabled/refresh

P7 工程状态 ADAPT 依赖 P4

  1. Goal/Todo — 从 GoalModeState/TodoPhase 生成 snapshot + events

关键设计决策

决策选择理由
v2 代码位置modes/rpc-v2/ 平行于 modes/rpc/v1 保留不动，v2 独立演进，切换由 CLI flag 控制
事件适配Adapter 层包装 AgentSessionEvent不重构 Session 内核；v2 DTO 从内部事件投影
Sequence 分配RPC 层 per-Session 单调计数器不修改 journal 格式；重连时从 journal 重建 watermark
Lease 实现进程内 + 文件锁（flock 或 lockfile）单进程模型下只需防多进程冲突
Schema 生成手写 TS 类型为权威源；JSON Schema 后续从类型生成当前无 schema gen 基础设施；先稳定类型再补工具链
ID 格式前缀 + Snowflake/ULID（如 rt_, ses_, run_）可调试、可排序、全局唯一

风险与缓解

风险影响缓解
AgentSessionEvent 缺少稳定 ID事件去重和 replay 困难Adapter 层生成 eventId；sequence 由 RPC 层分配
Session journal 无 sequence watermarkcrash 后无法精确 replayP3 引入 per-session sequence 持久化（sidecar 或 journal 尾部标记）
Approval 从 tier 系统到结构化 DTO 跨度大P5 工作量大先实现 tool_execute 类型；resource_access/integration_manage 后续补充
Backpressure 需要改造 stdout 写入当前直接 process.stdout.writeP2 引入 write queue + drain 等待
