1. 规范范围与退出定义

M6 不是单纯的 projection 可视化阶段，也不是扩大外部写入面的阶段。它必须同时完成冻结文档中的 Policy-aware recall、安全可恢复 projection、低噪音交互和真实 dogfood 证明。

必须交付

  • 修复 M5 遗留的 slash 测试回归，并建立统一的 Brain effective runtime policy。
  • 让 approved recall_policy 真正影响 recall query、候选过滤和预算，而不是只进入 prompt prelude。
  • 提供可按需读取、可迁移、可脱敏的 projection audit/debug read model。
  • 按 target 定义并实现 crash reconcile、有限 retry、CAS undo 和 blocked 处理。
  • 完成可重复的 10+ turn deterministic dogfood、真实 slash/session smoke 和真实会话报告。
  • 对 off、local、mnemopi、hindsight 四种 memory backend 给出成功或安全降级证明。
  • 形成明确 rollout 结论：扩大 opt-in、继续收敛或回退。

明确非目标

  • 不新增 projection target，不自动创建 hook，不改变工具权限。
  • 不实现 auto-approve；所有外部行为变化仍来自不可变 approve Decision。
  • 不把 audit 或 explain 变成每轮默认前台文本。
  • 不自动修改用户的持久化配置文件，不提交机器凭据和真实会话原文。
  • 不把自由文本历史升级为 recall policy、activation rule 或当前指令。
  • M6 完成后仍保持 san.brain.enabled=false 默认值；默认开启必须是后续独立决策。

执行纪律

纪律实施合同
M6.0 硬门禁配置状态机、projection 写入旁路、现有 slash 红测和验证命令未全部修复前，不并行推进 recall、schema migration 或真实 dogfood。M6.0 完成后固定一次全绿基线，后续切片不得破坏。
独立可回退切片M6.0-M6.5 每个切片都必须有独立输出、定向测试和退出证据；失败时只回退当前切片，不跨切片掩盖红测。
隔离数据面Deterministic test 和第一轮 projection smoke 使用临时 agent directory。真实用户 Brain store、managed skills 和 memory bank 只在前置门禁全部通过后接入。
行为版本化Recall template allowlist、selection policy、projection error mapping 和 dogfood fixture 使用稳定 policy/version id；报告记录 commit、配置 hash、DB schema、payload schema、policy version、backend 和 capability。

真实 Dogfood 分阶段启用

阶段配置进入下一阶段的条件
A. Review-onlymode=review-only，capture 开启，legacy autoRetain block。候选数受控、dedupe 正确、当前回答零变化、无 legacy 旁路写入。
B. Activationmode=activation，仍禁止 projection。相关任务正确命中；无关任务、敏感状态和当前用户冲突全部跳过。
C. Isolated Projectionmode=projection，使用临时 agent directory 和受控 backend。Managed skill/check suggestion reconcile、CAS undo、timeout、一次通知全部通过。
D. Real Backend使用实际 Mnemopi/Hindsight overlay；仍保持默认配置关闭。Receipt、scope、latency、失败降级和四 backend matrix 与合同一致。

立即停止条件

出现下列任一情况时立即关闭 dogfood overlay，保留 ledger 供排障，不继续观察更多 turn：

  • brain.enabled=false 时仍发生任何外部 projection。
  • Recall 或 activation 跨 scope、role 或项目污染。
  • 同一 projection operation key 产生重复外部写入。
  • CAS mismatch、人工修改或后续 revision 存在时仍覆盖外部状态。
  • JSONL 无法重建 SQLite 最终状态，或出现无法追溯到 Decision/owner 的 projection。
  • Debug、日志或报告泄露 secret、完整 evidence、凭据或未缩写的用户 home path。
M6 完成定义：不是“功能能跑”，而是配置 gate 无旁路、无关任务零污染、外部写入不重复、异常可恢复或安全 blocked、审计可追溯且默认体验安静。

3. 配置状态机与 Dogfood Overlay

Brain 的有效行为必须由一个共享 resolver 计算，session、slash command、memory compatibility 和测试不得各自拼接条件。

Effective runtime policy

interface SanBrainRuntimePolicy {
	enabled: boolean;
	captureEnabled: boolean;
	activationEnabled: boolean;
	projectionEnabled: boolean;
	legacyAutoRetainAllowed: boolean;
}
配置组合CaptureActivationProjectionLegacy autoRetain
brain.enabled=falseOffOffOff保持用户原配置
enabled=true, mode=review-only按 leaf 开关OffOff普通兼容可 warn；M6 dogfood 必须 block/显式关闭
enabled=true, mode=activation按 leaf 开关OnOffM6 dogfood 必须 block/显式关闭

5. M6.1 Policy-Aware Recall

Policy-aware recall 是冻结 M6 范围，不能以“projection dogfood”为由省略。它属于 runtime control plane，不是给模型阅读的历史建议。

核心合同

  • 只读取 approved、active、normal sensitivity、未过期且与当前 scope/role/task 匹配的 recall_policy。
  • queryTemplateId 必须来自静态 allowlist；未知模板跳过并写 audit，不把 id 当自由文本 query。
  • recall_policy 被 recall planner 消费后，不再作为普通 action 渲染进 Brain prelude。
  • 当前用户明确要求忽略 Brain/memory/history 时，recall policy 与 recall search 一并跳过。
  • 查询只使用 typed fields、当前 prompt、经过裁剪的 digest 字段和可信 scope；禁止拼接候选原文或 evidence 原文。
  • 所有 query template 文本放在静态 .md 文件，通过 with { type: "text" } 导入；动态字段用 Handlebars。

共享 selection

从现有 activation 中提取纯 selection 阶段，使 activation 和 recall 共用 scope、role、selector、confidence、expiry、sensitivity、current-user conflict 判断。两条路径不得各自实现近似匹配。

interface SanBrainRecallPlan {
	selectedPolicyIds: string[];
	queryTemplateId?: string;
	scopeKeys: string[];
	memoryTypes: string[];
	role: SanBrainActivationRole;
	limit: number;
	tokenBudget: number;
	skipReasons: Array<{ ownerId: string; reason: string }>;
}

每轮顺序

1解析当前用户、scope、role
2共享 selection 选择 recall policies
3构造 typed recall plan/query
4backend search 与安全过滤
5构造 ContextPacket 与 Brain prelude
6统一预算并写 activation/recall audit

Backend capability 与降级

BackendPolicy-aware recall 行为降级合同
off不执行 search。返回 backend_unavailable skip；不影响主 turn。
local当前无 structured search。返回 search_unsupported skip；不伪造 recall item。
mnemopi按当前 bank/scope 搜索；支持的 metadata 参与过滤。能力缺失字段显式记录，不放宽到跨项目 bank。
hindsight按 active bank、typed query 和 limit 搜索。超时或服务不可用时返回空 recall layer 并写 debug audit。
如果现有 MemoryBackendSearchItem 无法表达 type/scope metadata，M6 可以添加可选 typed metadata；不支持 metadata 的 backend 必须声明 capability，不得假装完成精确过滤。

6. M6.2 Audit 与 Debug Read Model

JSONL 继续是权威源，SQLite 继续是可重建物化视图。M6 不在 projection event 中重复存储可从 Decision 稳定派生的字段，而是建立 join 后的 debug read model。

持久化字段

字段来源合同
projectionIdProjection event同时作为外部 operation key；同一次 retry 必须稳定。
decisionIdProjection event指向不可变 Decision。
ownerId / Decision idempotencyKeyDebug 时 join Decision不在 projection event 重复存储。
target / state / attemptCountProjection event固定状态机与有限尝试。
revision / beforeHash / afterHashProjection event支持 CAS、reconcile 和 undo；按 target 允许为空。
errorCode / errorProjection event机器可读枚举 + 已脱敏短 message。
durationMs / receiptIdProjection event衡量主 turn 延迟并支持外部 receipt 对账。
notifiedAtProjection notification receipt保证 blocked 最多自动提示一次。

错误码最小集合

type SanBrainProjectionErrorCode =
	| "backend_unavailable"
	| "search_unsupported"
	| "invalid_draft"
	| "cas_mismatch"
	| "unsafe_undo"
	| "owner_unavailable"
	| "receipt_missing"
	| "stale_in_progress"
	| "attempts_exhausted"
	| "external_timeout"
	| "external_failure";

Schema 迁移

  • Projection JSONL event 以可选字段扩展保持向后兼容；旧 event 仍可读取。
  • SQLite 升级到新的 PRAGMA user_version，以原子 migration 增加 error code、duration、receipt 和 notification 字段。
  • 迁移测试必须从真实 v1 database fixture 打开并验证旧 projection audit 未丢失。
  • future DB version 继续拒绝写入；future JSONL payload 只读展示，不执行 projection/activation。

命令合同

所有 TUI/status/debug 文本必须执行 tab 替换、路径缩写、宽度截断和 secret redaction。外部异常不得原样进入主对话。

7. M6.3 Reconcile、Retry 与 Silent UX

状态机规则

当前状态自动路径显式命令下一状态
pending允许执行一次。/brain project 也可执行。applying → applied / failed / blocked
failed不在每个 prompt 前自动重试。仅显式 /brain project 重试，受 maxAttempts 限制。applying → applied / failed / blocked
applying / compensating启动 target-specific reconcile，不盲重放。命令显示 reconcile 结果。applied / compensated / blocked
blocked不重试；最多一次短状态提示。debug/explain 可读；修复外部状态后需显式新 Decision 或受控 retry。保持 blocked
applied / compensated跳过。只读展示。终态

Target-specific reconcile

TargetApply crash 后判定Undo / compensation
Managed skill create/update执行前计算预期 after hash；恢复时读取受管文件。匹配则补 applied receipt，不匹配则 CAS blocked。Create 仅删除匹配自身 after hash 的文件；Update 仅在当前 hash 匹配时恢复备份。
Check suggestion内容由 typed draft + projection id 确定；文件 hash 匹配即补 applied，否则 blocked。仅删除与原 after hash 匹配的建议文件。
Memory先查询 backend capability。支持按 operation/source 查询时对账 receipt；不支持时标记 receipt_missing blocked。Backend 无 projection-id compensation 能力时明确 unsafe_undo blocked。

延迟与资源门禁

  • 增加每次 external attempt timeout；dogfood 推荐值为 10 秒，超时记录 external_timeout。
  • 单 turn 处理 projection 数量必须有上限，避免积压 outbox 阻塞首个 prompt。
  • report 记录每个 target/backend 的 p50、p95、max duration；不得只统计状态数量。
  • projection failure 不改变 assistant 回答内容，不取消当前用户任务。

8. M6.4 Deterministic 10+ Turn Dogfood

Deterministic dogfood 是可重复验收，不依赖真实 provider 随机输出；真实会话报告不能替代它。建议固定 14 个 turn，覆盖完整闭环。

Turn / 操作场景必须观察到的合同
1用户声明稳定输出偏好。生成一个 pending profile candidate，不改变当前回答。
2独立上下文重复相同偏好。证据可 consolidation，不产生重复 active state。
3完全无关任务。无错误 activation、无错误 recall、无 Brain 前台噪音。
命令/brain approve 偏好。生成不可变 Decision；projection 遵守有效 gate。
4相关任务。approved state 被选中并写 activation audit。
5当前用户明确给出相反要求。Brain state 因 current-user conflict 跳过。
6构造可批准的 recall policy。policy 仍为 pending，不直接改变 recall。
命令approve recall policy。只批准 allowlisted template id。
7相关 recall 任务。policy-aware query 生效；结果遵守 scope/type/role/budget。
8无关 recall 任务。policy 不匹配，不召回无关记忆。
9Managed skill projection。成功路径只写一次，主对话 0 噪音。
10Check suggestion projection。typed content 和 after hash 可对账。
11外部人工修改后 undo。CAS mismatch blocked，不覆盖人工内容，只提示一次。
12模拟 applying 后 crash/resume。通过 target reconcile 得到 applied/blocked，不盲写第二次。
13Backend timeout/failure。当前任务继续；failed 不自动每 turn 重试。
14/brain debug all。完整链可追溯，输出已脱敏、截断、缩短路径。

测试原则

  • 每个新测试保护一个外部可观察合同，不断言内部 helper 接线或源码文本。
  • 不得使用 mock.module()；backend failure 使用 namespace import + vi.spyOn 或真实 adapter seam。
  • 配置测试读取实际 example YAML，通过 Settings loader 验证 effective values。
  • 生命周期测试必须覆盖 live session 与 resume/rebuild 两条路径。
  • No-noise 测试检查 provider/TUI 可观察输出，不以“函数没有 throw”代替行为断言。

12. Rollout 决策门禁

结论必要条件动作
扩大 opt-in所有 P0/P1 gate 通过；0 重复写、0 无关污染、0 secret 泄露；四 backend 合同成立；延迟在 timeout 内。保留默认关闭，发布推荐 overlay，并扩大内部 dogfood 用户。
继续收敛安全 gate 通过，但 recall precision、candidate 数、通知噪音或延迟未达标。保持当前 opt-in 范围，调整策略和阈值后重跑完整报告。
回退出现 global disabled 仍写入、跨 scope recall、重复外部写、覆盖人工修改、审计不可重建或敏感信息泄露。关闭 projection/activation overlay，保留 ledger 供排障，不扩大 rollout。
