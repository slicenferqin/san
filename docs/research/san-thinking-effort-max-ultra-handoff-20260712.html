三、已完成修复

1. 状态栏为 max / ultra 使用独立符号

packages/coding-agent/src/modes/theme/theme.ts 新增 thinking.max 与 thinking.ultra。Nerd 字体分别显示星标 max 与火箭 ultra；Unicode 分别为星形 max 与菱星 ultra；ASCII 分别为 [max] 与 [ultra]。两档继续复用顶档颜色 thinkingXhigh，但不再复用文案或图标。

packages/coding-agent/test/status-line-model.test.ts 增加回归契约，验证 Max/Ultra 的实际渲染标签与 XHigh 不同。

2. max 从旧 alias 升级为 canonical effort

packages/catalog/src/effort.ts 与 packages/agent/src/thinking.ts 均加入 Max、Ultra。packages/coding-agent/src/thinking.ts 的解析、描述、配置选择与 clamp 路径同步扩展。

XHigh 的 UI 描述从误导性的 “Maximum” 改为 “Extra-high”，Max/Ultra 各自有独立描述。

3. 修复 selector 与 literal :max / :auto 冲突

packages/coding-agent/src/config/model-resolver.ts 删除旧的 allowMaxAlias 分支；Max 直接按 concrete effort 解析。与此同时保留精确模型 ID、literal glob 和已知 literal selector 的优先级。 pi/<role>:max 仍是显式 Max，随后根据目标模型 ladder clamp。

相应 call site 已从 agent-session.ts、sdk.ts、model-registry.ts 移除旧 alias 开关。model-resolver.test.ts 覆盖 exact ID、glob、OpenRouter route、role alias、CLI 与 enabledModels 边界。

4. 修复设置项重复与预算缺口

packages/coding-agent/src/config/settings-schema.ts 去掉 [...THINKING_EFFORTS, AUTO_THINKING, "max"] 中重复追加的 Max；现在 Max/Ultra 各出现一次。 新增 thinkingBudgets.max 与 thinkingBudgets.ultra，默认均为 32768。

settings-manager.test.ts 验证默认 thinking 枚举包含 Max/Ultra 且全表无重复值。

5. ultrathink 能到模型真正的最高档

AgentSession.#applyAutoThinkingLevel 的 ceiling 从 Effort.XHigh 调整为 Effort.Ultra。旧模型仍由 clampAutoThinkingEffort 限制到自身最高档；显式声明扩展 ladder 的模型则可落到 Ultra。集成测试验证 Ultra 路径会跳过分类器。

6. 显式 GPT-5.6 扩展 ladder 不再被隐式平移

packages/catalog/src/model-thinking.ts 新增显式扩展 effort 检测：当自定义 GPT-5.6 模型明确声明 Max 或 Ultra 时，整条 ladder 原样保留，且不再自动附加通用的 shifted five-tier effortMap。 普通推断出来的 GPT-5.6 仍维持既有 shift 策略。

这消除了过去必须在自定义模型中偷偷写 effortMap: {} 才能让 Low/Max/Ultra 原样发送的 workaround。

7. OpenAI-compatible fallback 识别 Ultra

packages/ai/src/providers/openai-reasoning-fallback.ts 的已知值、排序和错误文本解析都加入 ultra。当请求 Ultra 而 provider 400 明示最高只支持 Max 时，会重试 Max 并缓存成功 fallback 参数。

OpenAI Responses、Codex Responses、Chat Completions、Azure、Bedrock、Ollama 等相关 wire/schema 类型也扩展到 Max/Ultra；Google 映射把两档安全折叠到其最高 HIGH。

8. Codex SSE 测试消除 WebSocket 等待干扰

packages/ai/test/openai-codex-stream.test.ts 中专门验证 SSE turn-state scope 的测试增加 preferWebsockets: false。原测试在当前环境会先等待 WebSocket 约 10 秒，但测试超时仅 5 秒；改后约 12ms 通过。这是测试确定性修复，不改变生产行为，接手者需要决定是否与本批一起保留。
