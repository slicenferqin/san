San 不需要再“内置 RTK”

当前仓库已经把 RTK / snip 一类的确定性输出过滤器移植进 pi-shell 原生执行层， 并通过 shellMinimizer.enabled = true 默认开启。准确的后续任务不是引入外部 rtk 二进制，而是把这套隐藏能力补齐安全闭环、可观测性和产品入口。

San HEAD: 2f6f7db58326 RTK snapshot: 5d32d0736f68 / 0.42.4 范围：代码审阅、只读运行探针、差异 benchmark
Decision
保留 San-native minimizer；拒绝把外部 RTK 放进运行链路。
  • GO 产品化现有 pi-shell minimizer
  • NO-GO vendoring / 自动安装 / 运行外部 RTK
  • BLOCK 先修许可证标注与原文恢复失败路径
  • USE RTK 仅作开发期对照、fixture 来源和规则参考
01 / Executive decision

这是“正式化已有能力”，不是新增第三方依赖

San 当前实现比外部代理更适合自身架构：审批、cwd/env、持久 shell、取消、超时、退出码、流式预览和 artifact:// 都仍由 San 掌控；过滤发生在命令完成后的原始 capture 上，不需要用 hook 把模型生成的命令改写成另一条命令。

一句话结论
现有方向是对的，但尚未达到“可证明无损、可量化收益、许可证闭环”的正式产品标准。

02 / Current implementation

当前能力已经完整穿过 Bash 主执行链

BashTool 把 minimizer 配置传入 native Shell。命令退出后，native 结果同时提供压缩文本、原文、filter 名和输入/输出字节数； TypeScript 层用压缩文本替换模型可见结果，并把原文存为 bash-original artifact。

默认与配置面 settings-schema.ts：enabled 默认 true，并已有 only、except、maxCaptureBytes、sourceOutlineLevel、legacyFilters。
Bash 接入 bash-executor.ts：构造 native options，命令完成后用 sink.replace(minimized.text)，再追加原文 artifact 引用。
原文保存 bash.ts：saveBashOriginalArtifact() 分配 bash-original 并写入原始文本。
原生引擎 engine.rs：命令识别、过滤分发、panic fail-open、capture 上限、pipeline overlay 和 safe-chain 路由。
过滤覆盖 filters/mod.rs：git、cargo、bun、go、JVM、Python、Node tests、Docker/K8s、GitHub/GitLab、lint、包管理器、文件列表、云命令等。
测试门槛 minimizer_fixtures.rs：大于等于 500 B 的 fixture 要求输出不超过原文 40%，小样本要求精确 snapshot。
本机已实际命中，不是“代码存在但没编进 addon”。

通过当前 san launcher 调用 executeBash("git status")，得到的是 San minimizer 的重排输出；当前 native addon 已包含这套实现。

03 / Architecture fit

内嵌过滤器比外部命令代理更适合 San

RTK 官方模式是 hook 改写命令，再由独立 RTK 进程执行目标命令并过滤输出。官方架构强调退出码透传、过滤失败回退原文和原始输出可见； San 已经在自己的执行器里实现同类不变量，因此再套一层代理只会制造双执行面与双过滤面。

Policy boundary

San BashTool

  • 审批与高危命令识别
  • cwd / env / internal URL
  • 超时、取消、后台任务
  • PTY 与 client-terminal 分流
→
Native execution

pi-shell + minimizer

  • 执行原始命令
  • 捕获完整 stdout / stderr
  • 按命令族确定性过滤
  • 不支持、管道、超限时 fail-open
→
Result boundary

OutputSink + artifact

  • 模型看到压缩结果
  • 原文保存为 artifact://
  • 保留退出码与结果状态
  • 继续使用 San 的截断与 TUI
维度外部 RTK 运行时San-native minimizer判断
命令接入hook / plugin 把 git status 改成 rtk git status原命令进入 San 已有 Bash 执行器San-native 更可审计
审批与安全新增一个可执行代理层，需重新证明参数与副作用等价沿用现有审批、路径和高危规则San-native 风险更低
取消 / 超时 / shell 状态要跨 RTK 子进程和目标子进程传播由 native Shell 与现有生命周期统一管理San-native 更一致

发布额外 binary、PATH、跨平台打包、版本同步随现有 native addon 发布San-native 更简单

不要同时启用两套。

若 San 内部 minimizer 已开启，再通过 hook 改写到外部 RTK，会出现双重过滤、原文归属不清、退出与取消链路变长，并让结果错误难以定位。

05 / Gaps and risks

评估发现的三个安全问题已在当前工作区修复，产品缺口仍在

最大风险不在“压得还不够多”，而在压缩后是否仍能证明原文可恢复、语义未被伪造，以及派生代码的许可证是否被正确保留。以下三项保留原始发现，并标明本次修复结果。

FIXED / LICENSE

RTK 许可证已从 MIT 错标纠正为 Apache-2.0

crates/pi-shell/NOTICE、Cargo 与 native npm metadata 已改为正确的 MIT AND Apache-2.0 组合，并把 MIT、Apache-2.0 全文与第三方 notice 纳入 crate、npm leaf 和 GitHub Release 分发链。

FIXED / RECOVERY

artifact 保存失败现在保留正常 raw 结果

executor 现在只在原文 artifact 成功落盘后应用 minimized text；回调缺失、返回空 ID 或抛错时保留 Bash 原有 raw/truncation 契约，写入异常会记录包含 filter 与字节统计的 warning。

FIXED / CORRECTNESS

git status 不再伪造尾部提示文件

long-status 解析不再把 untracked 区间的任意文本交给 tracked-path parser，只接受有真实缩进的路径；完整 dirty status fixture 已加入 Git 标准尾行，精确快照确认不会产生伪造的 ?? 项。

P1 / OBSERVABILITY

压缩元数据没有进入 session stats

native 已返回 filter、input bytes、output bytes，但 BashResult 丢掉了这些字段。 当前无法回答真实会话节省多少、哪个 filter 低收益、哪个命令经常 passthrough。

P2 / SURFACE

不同 Bash 路径体验不一致

本地非 PTY、后台任务、用户 ! 和 RPC 进入现有执行器；PTY 与 ACP client-terminal 不过滤是合理边界。 但 san shell 虽传入 minimizer，实时控制台仍打印原始流且忽略最终 minimized 结果，容易误判功能未生效。

P2 / UPSTREAM

外部 RTK 本身也不能当正确性 oracle

在 RTK 0.42.4 上实测 wc /definitely-not-present：原命令退出 1 且 stderr 有错误文本， RTK 仍退出 1 但 stdout/stderr 均为空。其 runner 的 stdout-only 路径没有重放 captured stderr，与项目文档描述不一致。

“始终保留退出码”不等于“始终保留诊断语义”。

退出码只能告诉 agent 失败了；若 stderr、失败块或警告被丢掉，agent 仍会重复调用、误判根因或采取错误修复。验收必须同时覆盖状态与关键信息召回。

06 / Recommended roadmap

三步把已有 minimizer 做成正式能力

PHASE A / DONE IN WORKTREE

安全与合规基线已封住

Apache-2.0 attribution、artifact 失败回退和 git status 假文件均已修复；相关 Rust、Bash executor、native npm 分发与 Homebrew metadata 测试已通过。

PHASE B / PRODUCT

让用户和 agent 看得见

在 Bash details/TUI 显示 filter · 原始→压缩 · raw artifact；提供清晰的 session toggle 与单次 raw bypass；保留现有 only/except 作为高级配置。

PHASE C / MEASURE

建立真实会话评测闭环

把 filter、input/output bytes、命令族、退出状态写入本地统计；用真实 San 任务比较 task success、重试次数、输入 token 和延迟；RTK 仅作为固定版本的差异对照。

建议的强制验收契约

  • 任何发生文本改写的结果，原始字节必须 100% 可恢复；保存失败不得继续返回有损文本。
  • 退出码、signal、cwd、env、超时、取消与后台任务语义不得因过滤改变。
  • 管道、重定向、显式 JSON/porcelain/raw 输出、交互/TTY 默认 passthrough。
  • 失败诊断、警告、文件位置、测试名、断言差异等关键事实应做结构化召回测试。
  • 按命令族对比真实模型 token，而不是统一使用“字符数 ÷ 4”。
  • 收益报告必须同时展示覆盖率：高压缩率不能掩盖大量 passthrough 或低质量过滤。
  • 上游每次同步都记录来源 commit、文件/算法、许可证、修改说明和本地回归 fixture。
  • PTY 保持原样；ACP 只有在能得到完整原文并进入 San artifact 系统时才做后处理。
推荐的功能命名：

对外称“Shell 输出压缩”或“Semantic Shell Output”，实现层继续叫 shellMinimizer。不要把产品能力绑定成“RTK 模式”，否则会模糊 San 自有执行契约与第三方来源边界。
