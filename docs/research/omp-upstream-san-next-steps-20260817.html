1. 结论先行

推荐顺序：先把“无副作用的一次性调用会在瞬时 Provider 故障时自动重试”做成共享底层能力；随后修正 OpenAI 兼容流在无终止标记时的静默截断；再以回环地址默认不变为前提补齐 Stats 的显式绑定地址。会话文件修复、自动压缩生命周期和 HTTP/2 恢复进入第二阶段，因本地结构差异分别适配，不能机械移植。
  1. 第一优先级是错误语义，不是新功能。这三项都直接减少“模型看似完成但实际没有完成”或“后台任务一次抖动就丢结果”的情况，符合 San 当前“敢挂一晚上”的目标。
  2. 第二优先级是持久化与恢复。会话 JSONL 损坏、压缩回调卡住、Cursor HTTP/2 reset 都会破坏长任务连续性；但它们需要对照 San 已有的 session storage、compaction queue 和 replay-unsafe 状态重写。
  3. 不上游架构迁移。OMP 的 Bazel、Nix、.omp 品牌和大型 Agent Hub/协议变化不属于 San 的近期交付面。

2. 上游最近发生了什么

官方提交页显示，main 当前顶端是 2026-08-17 的 PR #7824 合并提交；其父提交包含 GPT 模型上下文窗口下限与价格参数更新。官方 packages/coding-agent/CHANGELOG.md 的 v17.3.5 条目还列出一次性 Anthropic 重试、会话 JSONL 修复、HTTP/2 stream reset 恢复、Hub 生命周期修复和中途自动压缩不再等待扩展处理器等变化。

上游主题官方行为变化对 San 的判断
可靠性
Oneshot retry		 completeSimple 对瞬时故障可能返回 stopReason: "error" 而不是抛异常；上游新增共享重试器，覆盖 Anthropic overload/rate-limit 与 429/500/502/503/529，并读取 retry-after。 本地没有对应共享 helper；本地 instrumentedCompleteSimple 的标题、分支摘要、压缩和侧路调用因此存在“一次抖动即失败/空结果”的缺口。应最先适配。
可靠性
OpenAI stream		 流在产生内容后没有收到 finish_reason 就关闭时，不再把半句话当作干净 stop；insufficient_system_resource 也归入可重试的 Provider 错误。 本地已经有空生成重试和终止宽限逻辑，但目标文件仍缺少这个“非空且无终止标记”的失败合同；改动可限制在一个 Provider 文件与测试。
可观测性
Stats host		 omp stats、/stats 和 stats server 接受显式 --host，默认仍为 127.0.0.1；端口占用复用会校验 dashboard 身份和绑定地址。 San 当前 server 与两个入口都只有 port，且没有对应测试。适合做一个隔离的小改动；必须保留 San 已有的回环默认和拒绝不安全复用策略。
持久化
Torn JSONL		 磁盘写失败造成的部分追加会回滚到写前长度；恢复时标记畸形文件，在下一次追加前原子重写，并把持久化故障显式显示出来。 本地有 FileSessionStorage、流式 loader 和原子重写 guard，但没有对应的 malformed-record/rewrite 状态。收益高，适合第二阶段单独设计。
恢复
HTTP/2 reset		 Cursor 的 NGHTTP2_INTERNAL_ERROR/NGHTTP2_REFUSED_STREAM 在工具结果已经落盘且可安全继续时，走保留上下文的继续路径。 San 没有上游 turn-recovery.ts，但已有 unexpected-stop-classifier、replayUnsafe 和 retry cap。应移植判定合同，不移植文件结构。
生命周期
Compaction / Hub		 中途自动压缩不再等待可能挂起的结束事件处理器；无 reviver 的 parked、session-less agent corpse 可在新 spawn 冲突时安全回收。 San 的 compaction 生命周期位于 AgentSession 与 shared events，Hub 位于自有 tools/registry 结构；两项都值得做，但必须先画本地状态转换。

P0-A
一次性调用重试		 在 packages/ai 增加共享 helper；统一包住 branch summary、title、compaction、handoff 等无副作用调用。分类复用 AIError，不碰主 Agent turn 的 replay 规则。 同时处理 resolved error-stop 和 thrown error；有界尝试次数；尊重 retry-after；signal 在等待中取消时保留用户取消语义；非重试错误原样返回/抛出。 不把它接到已经产生可见文本、工具调用或图片副作用的主回合；不复制多个本地 retry loop。
P0-B
截断 OpenAI 流		 只改 OpenAI-compatible provider 的终态判断，并接入现有空生成重试；保留已有 usage-only 尾块宽限。 非空内容 + 无 finish_reason → retryable error；insufficient_system_resource → retryable error；空流仍进入既有 empty-completion retry；正常 stop/toolUse 不变。 不重写所有 Provider 的 stream terminal state，不把所有 EOF 都强行判错。
P1-C
Stats host		 为 stats server、san stats 和 /stats 增加 host 参数；回环地址仍是默认值。补 port-conflict 身份/地址校验。 默认只监听回环；显式 host 能在容器场景访问；IPv6 URL 正确加括号；不复用不同 host 的 dashboard；不停止无法确认属于 San stats 的进程。 不直接照搬 OMP 的包名、CLI 帮助或 wildcard 默认，不放宽本地 stats 安全边界。
P1-D
持久化与恢复		 先做 torn JSONL，再做 HTTP/2 reset；分别落在本地 storage/loader 与 retry classifier/session loop。每项独立提交和测试。 写失败后文件不再留下不可解析尾巴；下次追加前能重写；HTTP/2 reset 只有在工具结果已配对且没有 replay-unsafe 输出时才继续；重复恢复有上限。 不引入上游不存在于 San 的 turn-recovery.ts 文件形状，不把所有网络错误都变成可重放。
P2-E
Compaction / Hub		 先定位 San 的事件 emit、flushCompactionQueue、park/revive/CAS 入口，再分别适配 detached lifecycle emit 和 dead-corpse reclaim。 挂起的扩展处理器不能阻塞下一次 Provider 调用；可恢复 parked agent 不被误删；只有 session-less、无 reviver、无并发 park/revive 的 corpse 可回收；CAS 仍严格。 不把 OMP 新 Hub、live activity tracking 或 registry UI 整体迁入。

4. thinking-loop 与 catalog：有选择地吸收

Thinking loop：只取算法合同

OMP #8669 将循环检测重组为“所有模型可用的 exact suffix cycle + 特定模型的语义启发式”。San 当前已有 Gemini header、Grok 4.6 和多家族 guard，阈值与上游不同，不能整文件替换。建议先保留现状；若后续真实 dogfood 证明长周期 exact cycle 仍漏检，只移植 bounded tail detector 和 retryable 标记，并用 San 自有样本校准。

Catalog：生成，不手改

上游最新父提交只涉及 GPT 价格和上下文窗口 floor。San 的 models.json 是生成文件，按仓库规则应周期性运行 bun run gen:models，并对 resolver/descriptor 写回归测试；不为一次 upstream diff 手工改 generated JSON。

判断：上游 v17.3.5 的 xAI Responses、grok-4.5 默认路由、prompt cache、Nix 和 browser daemon 修复各有价值，但它们不是当前 San 的第一批移植目标。San 的本地 transport、配置命名和安全默认不同，应该在对应用户问题真实出现后单独做合同审查。
