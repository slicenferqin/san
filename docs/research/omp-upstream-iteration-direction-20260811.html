1. 方向判断

主线长会话与多 Agent 可靠性

持续处理 parked subagent 内存、handoff 终态、恢复/压缩、输出排空、Provider fallback、TPS/TTFT 统计和 WSL 空转 CPU。最近版本的密度说明“持续运行不失控”是当前最高优先级。

成熟度：已落地，并在 v17.2.9—v17.2.12 连续加固。

主线Agent 编排成为产品界面

Agent Hub 已升级为全屏 roster/inspector，展示聚合状态、用量、任务、模型、活动、血缘和 spawn tree；omp cleanse 已能并发分派修复。开放 PR 又继续补 goal quality gates、wayfinding、schedule、heartbeat、持久消息和 persona。

成熟度：控制台已落地；调度与目标治理仍在形成。

主线协议化、无头化与客户端平权

已落地 Claude/Codex 会话导入、Cursor modern exec bridge、MCP 兼容修复、session share；开放中的 RPC v3 明确提出 session protocol 与 native UI parity，MCP 也在跟进 2026-07-28 协议。

成熟度：已有多条接入路径；统一会话协议尚未合并。

支撑运行时内建化与性能工程

用自研 omptype 替换 arktype/zod，内建 ACP、日志、Markdown、模板、浏览器发现等基础件；原生侧合并 shell builtins，并自建音频后端。目标是降低冷启动、包体、构建链和第三方依赖波动。

成熟度：17.2.x 已大规模落地，预计继续做收敛和修复。

支撑桌面、浏览器与本地服务原生化

computer 已变成长驻 JavaScript 桌面会话，支持窗口级捕获/输入、可访问性树、剪贴板和流式截图；Browser Relay 接管本地 Chrome 标签页，LSP 可跨 OMP 实例共享。

成熟度：核心能力已落地，正在补平台与终端兼容。

支撑Provider 与外部生态互操作

近期集中补齐 Bedrock Mantle、ai&、GMI Cloud、Cursor、Codex、Anthropic OAuth、配额与账号选择；同时支持 Agent Plugins 1.0.0。竞争点由“支持多少模型”转向“凭据、额度、发现、fallback 是否可运营”。

成熟度：高频增量，仍会长期持续。

支撑扩展信任、安全与成本边界

已经加入显式 trusted extension、插件验证和 OMP 原生 software-security 工作流；开放 PR 正在推进拒绝写入/删除的 broker、fail-closed prompt gates 和成本上限。

成熟度：安全扫描已落地；通用权限与预算治理仍是候选能力。

持续TUI 可观测性与交互打磨

重点不是重写 TUI，而是让长 transcript、流式输出、Agent 活动、终端兼容、voice/image 和恢复提示更稳定。界面正在承担控制面观测职责。

成熟度：持续迭代，服务于上述主线。

4. 对 San 的直接影响

优先级处理建议原因
P0选择性吸收 v17.2.9—v17.2.12 的 subagent 生命周期、内存、handoff、恢复、输出排空和 Provider fallback 修复。这些是运行时正确性问题，与 San 产品差异无冲突，且能直接降低长任务风险。应按修复单元审阅/cherry-pick，不做整段版本合并。
P1专项评估 Agent Plugins 1.0、trusted extensions、MCP 新协议、共享 LSP、会话导入和 Cursor bridge。它们能减少 San 自建生态适配层，但涉及扩展信任、协议边界和当前分叉代码，应先做 contract audit。
P1持续跟踪 RPC v3，并用 San RPC v2 / 远程控制需求做字段和生命周期对照。这是最可能形成长期维护分叉的接口层；等上游方案稳定后再决定兼容、迁移或保留 San 扩展。
P2把 goal gates、wayfinding、schedule、heartbeat、durable Agent Hub 消息作为竞品设计输入，不直接移植。这些候选能力与 San 的 durable execution、watchdog、scope/ledger 和 peer messaging 高度重叠，语义冲突风险高于代码复用价值。
P2延后整套 omptype / utils / native builtins 合流，先独立量化启动、包体、构建和冲突成本。收益真实，但涉及面极大；在 3,600 提交、3,155 文件差异下，直接跟随会挤占 San 核心路线。

总体判断：上游正在快速补齐“Agent 平台”的横向能力，San 应优先借用其运行时修复和生态兼容，不应与上游同时维护通用底座；San 的差异化仍应放在宿主持有的 durable execution contract、可验证证据、恢复状态机和工作流语义上。
