San TUI 体验推进方案

结论：不重写渲染器，不照搬 Grok Build。下一波优先把 San 已经强大的底层能力变成用户能感知、能理解、能掌控的交互：统一动作入口、显式队列语义、结构化会话导航、终端自诊断、场景级 PTY 验收。

当前主要问题不是“画得不够快”，而是能力分散在快捷键、斜杠命令、隐藏手势和多个 overlay 中。用户需要记住系统，而不是系统根据上下文告诉用户下一步能做什么。

方案日期 2026-07-29 范围 packages/coding-agent + packages/tui 基线 Grok Build main 文档 + San 当前源码 目标 体验跃迁，不做技术栈迁移

1. 目标与非目标

这轮要交付的用户结果

  • 用户不查文档，也能发现主要动作、当前按键和不可用原因。
  • 运行中输入的“立即打断 / 下一步执行 / 稍后执行”含义清晰可见。
  • 长会话能按 turn / response / tool block 导航、折叠、复制和搜索。
  • 快捷键在当前终端失效时，San 能解释并给出真正可达的替代键。
  • 流畅度从主观感受变成有 PTY 场景、有指标阈值的发布合同。

明确不做

  • 不从 TypeScript/Bun 重写成 Rust；现有 differential render、native scrollback、DEC 2026 已是强底座。
  • 不复制 Grok 的内置、不可重映射按键；San 已有 namespaced keybinding manager。
  • 不先做“更多动画”和视觉皮肤；动画不能替代动作可发现性和状态可解释性。
  • 不新增第二套消息队列；UI 必须投影 AgentSession 现有 steering/followUp 队列。
  • 不把所有交互强行塞进全屏 alternate-screen；普通会话继续保留原生 terminal scrollback。

2. 现状判断：底层领先，交互层碎片化

渲染底座：保留

packages/tui/src/tui.ts 已有 30fps 节流、自适应 backpressure、component-scoped repaint、stable prefix、native scrollback commit/replay、resize 快路径和 loop watchdog。

输入语义：已有但难懂

InputController 已区分 Enter 的 steer 与 Ctrl+Q/Ctrl+Enter 的 followUp，队列也能 Alt+Up 恢复；但帮助页未完整说明，队列只是 transcript 下方的文本列表。

能力入口：割裂

热键在 /hotkeys，命令在 slash autocomplete，skills 在另一命名空间，终端状态在 debug 菜单；缺一个统一、可搜索、上下文感知的动作层。

核心产品债：San 的能力密度已经很高，但“入口密度”也很高。当前默认按键包括模型切换、thinking、plan、tools、external editor、history、hub、copy、retry、dequeue 等；多数只有静态帮助或 tips，没有按当前状态排序的操作提示。继续增加快捷键会恶化问题。

3. 从 Grok Build 借什么，不借什么

Grok Build 机制（官方文档） 对 San 的价值 San 原生实现方向
搜索式 Command Palette：动作、slash commands、skills 同一入口 P0 最大幅度降低记忆成本 建立 ActionRegistry；现有 keybindings、builtin slash registry、extension commands、skills 只做 adapter，不复制定义。
上下文 shortcuts bar：随焦点、运行状态、选中 block 变化 P0 让隐藏能力就地可见 从同一 ActionRegistry 选择 3–5 个当前高价值动作；窄屏按优先级收缩。
Prompt queue pane：可选择、编辑、send now P0 明确运行中输入的时间语义 基于现有 steering/followUp 队列做结构化 overlay；先查看/恢复/全部恢复，再评估 reorder。
Scrollback 焦点、turn/response 导航、折叠、复制、fullscreen P1 长会话从“滚动文本”变成可操作记录 为 TranscriptContainer 增加 selection/navigation model，不破坏 native scrollback tape。
按 terminal host 提供可靠备用键，并提供 doctor P1 减少“按了没反应” 扩展现有 terminal state/protocol probe，加入键盘事件 probe、按键 reachability 与冲突诊断。
Simple/Vim 两套 scrollback 模式 P2 power user 增益 先完成 action/navigation contract；Vim 只作为可选 keymap，不进入核心状态机。

外部事实来源：xAI Grok Build 官方 Keyboard Shortcuts。其文档确认 command palette、contextual shortcuts bar、queue pane、scrollback focus/navigation、terminal-specific fallback 和 keyboard help；具体实现细节未作为本方案前提。

4. 目标交互模型：一个状态，多个一致入口

Session / TUI state
Action availability
Palette / hints / keys
同一 command handler
关键约束：快捷键、palette、slash command、context hint 不得各自实现业务逻辑。它们只解析成同一个 ActionId，由同一个 handler 执行。否则显示的“可用动作”和真正执行的动作必然漂移。 
interface UiAction {
  id: ActionId
  title: string
  category: "session" | "input" | "view" | "agent" | "tool"
  keywords: readonly string[]
  when: (state: UiActionState) => boolean
  disabledReason?: (state: UiActionState) => string | undefined
  priority: (state: UiActionState) => number
  run: (ctx: InteractiveModeContext) => void | Promise<void>
}

这不是要制造通用 command framework。只抽出用户可触发动作的最小共同合同；已有 slash command 参数解析、extension 注册、skill 执行保持原样。

5. 分阶段落地

P0 A. Action Palette + 上下文操作条

先做

用户合同

  • 一个固定、跨终端可靠的入口打开动作搜索；同时保留 ? 作为易发现入口。
  • 搜索范围：app actions、builtin slash commands、extension commands、skills。
  • 每项展示当前绑定、来源、是否可用；不可用项解释原因。
  • 编辑器下方只显示当前状态最重要的 3–5 个 hints，而非全量快捷键。

代码落点

  • 新增 action registry：靠近 modes/controllers，消费 KEYBINDINGS 和现有 command registries。
  • 复用 SelectList/SettingsList 构建可搜索 overlay。
  • keybinding-hints.ts 升级为 action hint renderer；所有 surface 从 registry 取 display key。
  • /hotkeys 改为 registry 的完整只读视图，消除当前手写表格漂移。

验收

  • 每个 registered action 可被搜索、可执行或显示明确 disabled reason。
  • 用户 remap 后 palette/hint/help 同帧显示新按键。
  • 80 / 120 / 200 列下不溢出；窄屏按优先级丢弃。
  • overlay 打开/关闭不清空 draft、不改变 scrollback。

P0 B. Queue Center：把运行中输入变成可管理对象

与 A 同批

用户合同

  • 队列非空时显示单行摘要：Now 1 · After yield 2，而不是永久展开所有文本。
  • 打开 Queue Center 后可查看完整消息、类型、图片数和执行时机。
  • 支持：恢复选中项到 editor、恢复全部、清空用户队列、立即发送选中项。
  • 输入框顶边/提示条明确：Enter 当前是 steer 还是 normal send；follow-up 键当前做什么。

源头修正

  • 给 AgentSession 暴露稳定的只读 queue item DTO（id、kind、preview、images、attribution），不再只返回字符串。
  • 所有 mutation 仍由 session 队列 API 完成；overlay 不碰 agent core arrays。
  • 保留 Alt+Up 的 LIFO 快捷路径；Queue Center 提供精确选择。
  • advisor/hidden companion 不伪装成可恢复用户消息；UI 显示范围与 mutation 权限一致。

验收

  • steer/followUp/compaction queue 在一个投影视图中顺序稳定。
  • 带图片消息恢复后 marker 与图片索引仍一致。
  • 队列 mutation 与 stream unwind 竞争时无丢失、重复或误发。
  • focused subagent 与 main session 只显示各自队列。

P1 C. Conversation Navigator：长会话可定位、可操作

第二批

用户合同

  • Tab 或 palette 动作进入 conversation focus；draft 原样保留。
  • 按 user turn、assistant response、tool block 跳转。
  • 选中 block 可折叠/展开、复制正文/元数据、打开 fullscreen viewer。
  • 会话内搜索跨用户、assistant、tool label/result，结果可跳转。

实现边界

  • 在 TranscriptContainer 上建立 block index：稳定 block id、kind、row range、collapsed state。
  • selection 是 viewport overlay，不重排或重写已提交 native scrollback。
  • 手动 fold 必须在 streaming finalization 后保持，除非用户显式清除。
  • 先提供 Simple keymap；Vim keymap 只映射 action，不分叉逻辑。

验收

  • 10k+ 行 transcript 中 turn jump 不触发 O(history) 全重绘。
  • 进入/退出 focus 不改变 terminal history bytes。
  • streaming 中展开/折叠不会产生重复 scrollback 行。
  • selection、search、copy 对宽字符和 ANSI 内容正确。

P1 D. Terminal Doctor + 场景级 PTY 验收

贯穿第二批

用户合同

  • Debug → Terminal State 升级成 Terminal Doctor。
  • 展示 detected host/mux、keyboard protocol、关键 chord 是否可区分、fallback 建议。
  • 交互 probe 让用户按指定键，San 显示收到的 canonical key event。
  • 冲突或不可达 binding 在 palette/help 中直接标记。

验证矩阵

  • 至少覆盖 Ghostty/Kitty、iTerm2、WezTerm、VS Code family、Windows Terminal、tmux、SSH+tmux。
  • 场景：长 streaming、队列编辑、overlay、resize、IME、图片、selection/copy、cancel/exit。
  • 复用现有 VirtualTerminal、process-terminal harness、render-stress reducer；补真实 PTY scripted scenario。

发布门槛

  • 输入到可见反馈 p95 ≤ 50ms（不含 terminal host 自身调度）。
  • 稳定 streaming frame p95 ≤ 16ms；极长 transcript p95 ≤ 33ms。
  • 连续 resize 后最终 frame、cursor、scrollback oracle 全部一致。
  • 关键 action 每个目标终端至少有一个经 probe 验证的可达入口。

P2 E. 精修：Vim keymap、鼠标命中、视觉节奏

后置

只有 A–D 的行为合同稳定后再做：可选 Vim scrollback keymap、点击 block 选择、hover、queue row mouse action、focus transitions、动画降噪。所有功能必须走 ActionRegistry 和同一 selection model；不得新增旁路。

6. 首批建议拆分（可直接开工）

切片 产物 主要文件/模块 依赖
A1 动作合同 UiAction、state projection、builtin action adapters、单元合同测试 modes/actions/*（建议新目录）、controllers 无
A2 Palette UI 搜索、category、binding/source/disabled reason、执行 components + SelectList A1
A3 Context hints editor 下方/顶边按状态投影 3–5 个动作；/hotkeys 改为生成 keybinding-hints.ts、interactive layout、hotkeys markdown A1

推荐集成顺序：D0 先建立基线；A1 与 B1 并行；A2/A3 接 A1；B2 接 B1+A1。首批完成时，用户已经能发现所有主要动作、理解运行中输入，并精确管理队列——这是最小可感知跃迁。

7. 体验指标：避免“感觉更顺”无法验收

可发现性

  • 主要动作（send/interrupt/queue/model/plan/tools/hub/history）100% 可从 palette 找到。
  • 关键状态（idle/streaming/compacting/focused subagent/queue non-empty）均有上下文 hint。
  • 帮助、palette、hints 的 binding 来源为同一 registry，零手写漂移。

掌控感

  • 队列 mutation 每次有即时、可逆的可见结果。
  • draft、attachments、queue、focused session 切换无隐式丢失。
  • destructive action 均有二次动作或明确确认，普通 navigation 不弹确认。

响应性

  • 采集 render cost、schedule delay、input-to-paint，不只采 event-loop stall。
  • 测量 idle、streaming、large transcript、overlay、resize 五类 workload。
  • 性能报告附 terminal/mux/capability 与 frame percentile，能复现而非仅给 flamegraph。

兼容性

  • 任何宣传的 modified key 必须有 terminal reachability 证据或稳定字符键替代。
  • tmux/screen/ConPTY/IME/Kitty graphics 不因新 overlay/navigation 回归。
  • headless/RPC/ACP 不加载交互 UI 状态机，也不改变消息语义。

8. 风险与控制

风险 为什么危险 控制
ActionRegistry 变成“大一统框架” 扩展点过多，迁移成本吞掉体验收益 只收用户可触发动作；参数化业务、command parsing、权限继续留在原模块。
Queue UI 与 agent queue 状态分叉 并发 stream unwind 下会误显示、误删、重复发送 session 提供稳定 DTO 和原子 mutation；UI 不持久化副本，只持 selected id。
Conversation focus 破坏 native scrollback San 当前最强的渲染资产可能被全屏选择模型绕开 selection overlay 与 block index 分离；已提交 tape 不重写；PTY oracle 先于视觉精修。
终端特判扩散 每个 component 自己判断 host 会形成不可维护矩阵 terminal capability/reachability 统一在 TUI 层；action 只消费 capability verdict。
动画抢占帧预算 现有 loader、thinking dots、stream reveal、magic shimmer 已并发 新增视觉反馈默认静态；统一 motion budget，重负载时主动降帧/停动画。

9. Definition of Done

首批（A+B+D0）完成条件

  • Palette、context hints、/hotkeys 共享动作和按键事实源。
  • 队列可查看、选择、恢复、清空、立即发送，图片与并发路径有合同测试。
  • 终端宽度 80/120/200、idle/streaming/compacting/focused-agent 场景均验证。
  • 记录首批前后 input-to-paint/frame-cost 基线，无显著回退。
  • coding-agent UI suite、tui suite、bun check、真实 CLI smoke 通过。

整轮（A–D）完成条件

  • 长会话具备 turn/response/block 导航、fold、copy、fullscreen、search。
  • Terminal Doctor 能检测关键按键并给出当前终端的有效入口。
  • 目标 terminal/mux 矩阵有脚本化 PTY evidence；scrollback/cursor/frame oracle 无回归。
  • 新增用户合同进入 packages/coding-agent/CHANGELOG.md 和 packages/tui/CHANGELOG.md 对应 Unreleased。
  • dogfood 以真实长任务运行，不以组件快照代替端到端体验验证。

10. 决策结论

San 下一波 TUI 不应从 renderer 开始，而应从 interaction model 开始。

现有 renderer 已经解决了大量难题：差分输出、同步输出、native scrollback、稳定前缀、长流式内容、resize 和 terminal capability。当前高 ROI 是把这些能力托住的复杂产品语义收束成一套用户能看见的动作系统。

推荐立即启动 A+B+D0。它们能在不动会话核心语义、不重写渲染技术栈的前提下，最快产生可感知提升；Conversation Navigator 和 Terminal Doctor 在此基础上完成第二次跃迁。
