P0 · 最终 rendered ContextPlan 可越过自己的 hard cap

fitMaterialsToPlanBudget 用的 shell 与最终 wire 不同，quality-gate 字段在第二次 render 后把消息推过 planTokenBudget。

planner.ts:184 以固定 qualityGate: pass 和无 projectedInputTokens 的临时 audit 拟合 material；:349 随后才把真实 gate/audit render 到 provider message。最终模板会增加 projectedInputTokens、reasons 和 outcome 行，但没有再验证或回退 material。 

settings.planMaxTokens = 135
preliminary shell       = 132 tokens
final provider plan     = 162 tokens
coverage                = [u1, a1]

真实两轮 AgentSession probe：audit budget = 135，发送的 ContextPlan = 149 tokens

这不是只发生在无法容纳空 shell 的极端降级：cap=135 足以容纳预估 shell，仍保留 digest coverage 并发送超 cap 的 replacement。它违反第四轮修复声明“material-level cap / final wire cap”，也使 audit 的 planTokenBudget 不再能描述实际 provider 输入。必须在真实 audit 上拟合，或在最终 render 后重新逐 material 去除并在空 shell 仍超 cap 时显式 fail-close，而不是继续发送超额消息。
