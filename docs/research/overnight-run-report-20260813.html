3. 关键决定(及理由)

  • RPC 观测 ack/游标:决定不做。San RPC 是 stdio 子进程——连接即进程生命,不存在"断线但进程还活着"的窗口;desktop 重启走 --continue 全量重建,已被事实报告验证可靠。v3 报告也将其列为可后置。在 stdio 传输下做序号/重放缓冲是为不存在的故障模式写代码。若未来上 socket 传输,再按 v3 规格实施。
  • merge queue / require-up-to-date:留给你决策,未动手。#15 的 stale-base 漏检(PR 绿、合后 main 红)的对症药是 GitHub 分支保护 "require branches to be up to date" 或 merge queue。但这改变你的合并工作流(每合一个 PR 其余全部要 update/重跑 CI,今晚这种 5 PR 并行的节奏下摩擦显著)。属于流程变更,不该过夜擅自改仓库设置。建议:公开仓库 merge queue 免费,如果并行 PR 是常态,值得开。
  • CI"卡 4 小时"复盘修正:逐 run 核查发现当时是 self-hosted runner 排队,不是 job hang(test job 全部早有 20-25 分钟 timeout)。真正缺口是 check/native 构建/install smoke 无 timeout(GitHub 默认 360 分钟)——#28 补齐,release job 有意不设限。
