1. 交付结论

结论：首批 P0 候选已完成 San 结构适配、合同测试、跨域审查和包级验证。没有引入 Agent Hub、goal/schedule、Agent Plugins、RPC v3、omptype 或 shell/native 大重构，也没有放宽 San 现有 execution-control 与 terminal session 边界。
  • dispose 现在按“阻止新工作 → 排空所有权内异步尾部 → seal/close → 释放重内存”的顺序收敛；超时尾事件最终结束后会再执行一次内存终态化。
  • 高 TPS 下，交互模式只在 33ms 窗口消费最新累计快照；尾事件严格排在 pending flush 之后。
  • Codex Trusted Access / cyber policy 拒绝先轮换同 Provider 的兄弟账号；账号耗尽后才进入 San 原有 route/model fallback。
  • task 子 Agent 与父会话共享性能聚合存储，assistant turn 的 TPS/TTFT 能进入父会话的模型统计。
  • manual handoff 的空生成明确失败，harness abort reason 原样保留；auto handoff 仍保留既有 compaction fallback。
  • print mode 等待最终 stdout 回调；Loader 根据真实绘制成本退避，避免慢终端持续空转。

3. 关键运行时合同

会话 dispose / seal

beginDispose同步拒绝新工作
abort & drain停止 provider 并排空尾部
seal升起不可逆写屏障
close等待 writer 与 backend
release清除重内存副本
reopen新 manager 从磁盘恢复

旧 SessionManager 在 dispose 后是终态对象，不能继续追加或被当作新会话复用；恢复必须新建 manager 并从持久 transcript 打开。这一边界同时解决 parked/keep-alive subagent 长驻内存和旧异步写覆盖新会话的问题。

AccountPolicy 重放安全

错误分类在 Auth/ContentBlocked 之前识别 cyber_policy 与 Trusted Access 拒绝。仅当尚未提交文本、图片或 tool call，且不是 abort/context overflow 时才允许换账号重放；thinking-only 仍属于安全窗口。maxRetries=0 不会跳过兄弟账号遍历，凭证轮换累计 attempt，route/model fallback 才重置预算。

流式与输出顺序

message_update 只合并 TUI 的累计渲染快照，不改变 AgentSession 对上游 delta 的逐事件处理。print mode 通过 stdout callback 队列等待最终 JSON/text 记录落入输出流，写入错误会显式抛出。
