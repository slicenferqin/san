San v0.3 · Technical Implementation · 2026-07-08

Brain / Experience System：从会话账本到可激活脑状态

本文把顶层设计落到现有代码：复用 session JSONL、TurnDigest、ContextPacket、memory backend、managed skills 和 Auto-Learn 的安全边界，新增一层 Brain Runtime，负责 profile notes、experience candidates、consolidation 和 activation。

规范性修订： 本文已按 san-v0.3-p0-design-freeze-20260710.html 收敛。P0 文档在命名、scope identity、生命周期、状态权威、投影、撤销、Prompt authority 与阶段顺序上具有最高优先级。

结论

v0.3 不应新建一个“万能记忆系统”。 正确实现是把现有 san.contextSteady 的会话摘要能力、memory.backend 的存取能力、managed-skills 的技能落地能力和 San Loop 的审计能力连接起来，在它们上方新增一个可解释、可撤销、可渐进启用的 Brain Runtime。
JSONL 是证据账本 session JSONL 继续保存原始事件、custom entries 和调试证据；Brain 不把它原封不动写成长记忆。
Profile 是合作状态 用户偏好、画像事实、合作决策、项目事实需要清洗、合并、标注 scope/evidence 后成为可注入的稳定状态。
Experience 是行为改变 用户纠偏、失败、成功路径和 review 结论要被解释成下一次如何行动：state、workflow、skill、risk、check 或 recall。

当前实现基线

现有模块已提供能力v0.3 如何复用
session/*.jsonl CustomEntry 不进 LLM context；CustomMessageEntry 可注入 context；appendCustomEntry() 是持久化扩展状态的稳定入口。 新增 san.brain.* custom entries 保存候选、决策、激活记录和解释证据；不改变 JSONL 基础格式。
context-steady TurnDigest 在 settled turn 后生成；ContextCheckpoint 折叠旧 digest；ContextPacket 在下一轮开始前注入稳定上下文。 Brain 的候选提取优先消费 TurnDigest，并把已批准的 profile/experience 作为新的 brain state layer 注入。
memory-backend 互斥选择 off/local/hindsight/mnemopi；提供 status/search/save；ContextPacket recall 可读 backend 搜索结果。 Brain 不替代 backend。backend 只负责 searchable notes / external memory；Brain 负责判断是否该写、写什么、如何影响行为。
autolearn 会话结束后被动或自动触发 learn nudge；learn 可保存 lesson，并可创建 managed skill。 v0.3 复用 managed skill 写入安全边界，但把“让模型自己 learn”升级成结构化候选、审批和撤销。
managed-skills 写入 ~/.san/agent/managed-skills；严格 name/description sanitize；authored skill 优先级高于 managed skill。 Skill solidification 的落地层。Brain 只生成/更新 managed skill draft，不覆盖用户手写 skill。
san-loop 有 run/event/review report custom entries，可记录 Supervisor findings、retry、checks。 Experience source。失败模式、review 结论和 retry outcome 可转成 risk reflex、workflow 或 check candidate。

集成点规格

位置接入点顺序降级策略
AgentSession settled turn 把 #generateTurnDigest() 与 BrainController.captureTurn() 链接为同一 Promise，并由现有 #trackPostPromptTask() 跟踪。 Capture 晚于 digest source span 和持久化；digest skip/fail 时可使用 message-span deterministic fallback。 记录 san.brain.error；绝不阻断 agent_end、session 保存或下一轮输入。
下一真实用户 prompt M2 起最多等待 pending capture 150ms。 超时则本轮不使用新 state，下一轮再生效；synthetic continuation 不等待。 禁止无限等待或回退成全量 JSONL 扫描。
prompt prelude M4 新增统一 injection planner，再接入 Brain State。 Brain authority 低于当前用户、项目规则、真实工具结果和当前任务状态。 store 失败时跳过 Brain layer，并写具体 activation error。
session stop / dispose 有限等待 tracked task；未完成 ledger 在启动时 reconcile。 stop 后不自动继续用户任务，不把 pending question 当 approval。 保留 candidates 和 outbox 状态，允许显式重试。

Claim、Dedupe、Conflict 与决策

Key生成规则碰撞语义
claimKeyscope + type + normalized subject + normalized predicate同一命题槽位。
dedupeKeyclaimKey + normalized value/action相同值合并独立 evidence、repeatCount 和 lastSeen。
conflictKey会产生互斥行为的 selector/action 槽位不同值形成 conflict；批准新值必须生成 supersede Decision。

阶段规则

  • M1-M2 只写 Candidate；不产生 active state。
  • M3 通过显式 approve/discard/undo 生成不可变 Decision。
  • M4 仅允许低风险 typed action allowlist 参与受限 auto-apply。
  • other、skill、check、跨 scope 或文件写入候选永远需要 review。

存储设计

1. Session JSONL：审计权威

Candidate、Decision、Projection、Activation 和 Error 都先写 append-only CustomEntry。Decision 不修改旧 entry；undo、supersede、降 scope 都写新 Decision。

san.brain.activation
san.brain.error

2. SQLite：可重建 materialized state

~/.san/agent/brain/brain.sqlite
  candidates(candidate_id, kind, scope_kind, scope_key, claim_key, dedupe_key, conflict_key, payload_json, created_at)
  decisions(decision_id, owner_id, action, previous_revision, next_revision, idempotency_key, payload_json, created_at)
  active_states(owner_id, revision, scope_kind, scope_key, status, payload_json, updated_at)
  evidence_refs(owner_id, evidence_key, payload_json)
  projections(projection_id, decision_id, target, state, attempt_count, revision, before_hash, after_hash, error, updated_at)
  activations(activation_id, turn_id, role, selected_ids_json, token_allocation_json, rendered_hash, created_at)
  • 启用 WAL、busy_timeout 和 foreign keys。
  • 数据库结构只使用 PRAGMA user_version 原子迁移。
  • Decision apply、active revision 和 outbox insert 在同一事务。
  • future JSONL schemaVersion 只展示，不投影、不激活。

3. 外部 projection

Memory、managed skill 和 check 不是 source of truth。Projection 状态固定为 pending/applying/applied/failed/compensating/compensated/blocked；重试必须使用 idempotency key，undo 必须使用 revision/hash CAS。

Brain State 注入

M4 才接入 #buildBrainStatePrelude()。它由统一 injection planner 选择 active state，返回 hidden CustomMessage；M1-M3 不注入、不改变 agent 行为。

Authority来源Brain 规则
最高System/developer、项目规则、工具安全合同永不覆盖。
高当前真实用户指令、workspace 和真实工具结果冲突时跳过 Brain state。
中当前任务状态、San Loop accepted reviewBrain 只能补充，不能改写。
低Brain active state只提供可解释默认行为。
最低ContextPacket、memory recall、历史文本作为不可信历史数据。
Renderer 只消费 typed fields，JSON-escape 文本、移除控制字符并限制单项长度。历史中的 XML、Markdown fence、命令和工具语法不得升级为当前指令。

相关性筛选与 Typed Activation

  1. Scope gate：使用 scopeKind + scopeKey；不按 cwd basename 匹配。
  2. Task/role gate：匹配 taskFamilies、commands、fileGlobs、languages、roles 和 riskClasses。
  3. Conflict gate：当前用户、项目规则或真实工具证据冲突时跳过。
  4. Priority：standing decision > risk rule > project fact >低置信 profile。
  5. Global cap：Brain + ContextPacket + San Loop 共用真实执行的总预算。

Typed action 只允许 prelude_fact、risk_rule、workflow_suggestion、skill_reference、check_suggestion 和 recall_policy。v0.3 不允许历史状态自动创建 hook、执行命令或改变工具权限。

Auto-Learn、Legacy Memory、Prompt 与迁移

主题v0.3 规则
Auto-Learn保持现有功能；Brain 不把 learned.md 当 source of truth。一次性 migration 只生成 pending candidates。
Legacy autoRetainBrain disabled 时保持现状；review-only dogfood 必须关闭；projection mode 下长期自动写入只能来自 Brain outbox。
已有用户配置检测 autoRetain=true 时显示具体告警并进入 compatibility mode；不静默改写配置文件。
Prompt 输出LLM classifier 使用 schema 输出；无证据返回空数组；每项必须带 source refs。模型不得生成可执行 activationRule。
Prompt 去重Brain active state、Auto-Learn capture instructions、ContextPacket 和 memory recall 分层；统一 planner 控制总预算。
Schema migrationSQLite 使用 PRAGMA user_version；JSONL future schemaVersion 只读展示。

最小闭环验收

  1. 用户纠正：“遇到陌生现代项目先查 primary source”。
  2. M2 生成 profile/experience Candidate，包含 scope、claim、typed risk rule 和 evidence refs。
  3. /brain inbox 与 /brain explain 能在行为变化前解释候选。
  4. M3 经用户 approve 生成 Decision；undo 已可用，仍不注入 prompt。
  5. M4 activation planner 在下一相关任务注入该 risk rule，并记录 scope match、token allocation 和 rendered hash。
  6. San 先读取 primary source；用户执行 undo 后该 rule 不再激活。
  7. M5 前不自动写 memory 或 managed skill。
