3. 兼容边界

Canonical 写入：@san/*、san、~/.san、.san、SAN_*、san-plugins.lock.json。
Legacy 只读/回退：@oh-my-pi/* 等旧 scopes、~/.omp/.omp、OMP_*/PI_*、omp-plugins.lock.json。新值始终优先。
  • omp-legacy-pi-bundled: 是编译模式插件解析协议的一部分，不是用户品牌文字，继续保留。
  • Claude device-id hash domain、session/message type discriminator、数据库键、网络协议字段不得因品牌清理而改变；改变会破坏已有数据或身份稳定性。
  • my.omp.sh 当前仍是实际 relay/share 服务。没有已部署 San 域名前，代码和文档保留域名并明确 legacy service。
  • 已发布 changelog 不改；旧仓库 issue/PR 链接是来源证据，不重写成不存在的 San issue。
  • PI_* 中部分变量属于底层库公开契约。新增 SAN_* 时使用 San 优先、PI/OMP 回退；不做静默删除。

5. 配置发现与系统提示词数据流

  1. getConfigDirName()：SAN_CONFIG_DIR → PI_CONFIG_DIR → .san。
  2. getAgentDir()：由 profile-aware dirs resolver 生成 ~/.san/agent 或 ~/.san/profiles/<name>/agent；SAN_PROFILE 优先于旧 profile vars。
  3. native discovery：从最近的项目 .san 和 active profile agent dir 载入 SYSTEM、skills、rules、commands、plugins 等；Claude/Codex/Gemini 等 provider 目录是外部工具兼容来源，不应重命名。
  4. loadProjectContextFiles()：通过 capability 聚合 AGENTS/CLAUDE 等 context，再展开 @path imports，按 depth 排序，最后去除内容完全相同的重复项。
  5. buildSystemPrompt()：组合 base/custom prompt、SYSTEM.md、project prompt、context files、always-apply rules、skills、工具清单和工作站信息；重复规则必须在渲染前按规范化段落消除。
  6. discoverTitleSystemPromptFile()：项目配置优先于用户配置；路径来源使用统一 config resolver，保证 profile 与项目优先级一致。
