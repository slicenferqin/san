1. 结论与完成标准

决策：不新增第二套执行控制。以现有 ExecutionRuntime、TaskContractRegistry、ProviderHealthRegistry、ExecutionScheduler、Watchdog 为唯一控制面；把它们接入真实的 AgentSession、task 子代理和 San Loop 路径。所有运行状态由宿主持有，模型文本只提供建议或观测，不能批准完成、切换终态或解除外部阻塞。

用户问题不是“缺少重试”，而是控制面未接线：实现已存在，但关键运行路径没有共享同一 scope、没有在 provider/task 事件后更新 scheduler、San Loop 仍允许绕过 scheduler。最终验收必须同时证明：

  • 同一父请求及其 task 子代理共享一个 executionScopeId；独立用户请求和并发父请求隔离。
  • provider 冷却、认证失败、速率限制会改变 scheduler 可运行性；无健康 provider 时不再发起模型调用。
  • 重复 work/strategy/failure 被 Watchdog 识别；无新证据时转诊断、等待或终止，而不是继续消耗 token。
  • 只有满足 host evidence gate 才能 completed；只有类型化外部阻塞证据才进入 needs_user。
  • 分支切换、会话重放、abort、dispose 后不遗留订阅、活动 scope 或幽灵运行。
  • 确定性故障注入覆盖 Grok 鉴权失败、流中断、重复工作、无新证据、外部依赖、预算耗尽。

2. 冻结的跨模块契约

契约冻结规则原因
Scope 身份每个顶层用户执行创建一个 scope；父任务通过只读字段把该 ID 传给子代理。子代理不得创建、切换或释放 scope。保证父子预算、证据和 provider 状态共享，同时隔离并发父请求。
Scope 解析优先级显式 task contract scope → child 固定 scope → runtime active scope → 根会话按 host request 新建。禁止用全局单例猜测。避免 active scope 在并发/分支切换时串线。
持久化仅使用当前 SessionManager 分支的自定义 entries；回放恢复 scope、task contracts、provider health、progress window 与终态。不得扫描其他分支。防止分叉会话污染。
事件职责AgentSession 发布 request/response/provider 观测；task registry 发布 contract 生命周期；ExecutionRuntime 订阅并推进 ledger/scheduler；San Loop 只调用 runtime 公共 API。单一写入路径，避免各模块重复计算状态。
终态completed 需 host-owned evidence gate；needs_user 需 SupervisorExternalBlocker；预算耗尽使用新增 budget_exhausted，不伪装成外部阻塞。保护终态语义和 UI/自动恢复决策。
Provider 观测仅持久化脱敏字段：provider、model、失败类别、冷却时间、请求计数、稳定失败指纹。原始错误、token、headers 不进入 ledger。避免凭据泄漏，同时保留可诊断性。
Watchdog 动作reject/reuse_duplicate 不重新调度；suppress_unchanged_poll 事件驱动等待；diagnose 触发一次 supervisor 恢复决策；repair_state_drift 重新同步分支/runtime。将“检测”变为可执行控制，而不是日志。
禁止：以 worker/supervisor 自述文本作为外部阻塞证据；在 task 子会话中自行创建 runtime；用 blocked 同时表示外部依赖、预算耗尽和 provider 暂不可用；保留旧的 scheduler 可选旁路。

7. Work Packets：Wave 2 并行三路

SessionWire：顶层生命周期与 provider 观测

  1. 在 createAgentSession() 完成 SessionManager/ProviderHealthRegistry/TaskContractRegistry 初始化后创建唯一 ExecutionRuntime，并交给 AgentSession 和 task 工具。
  2. 每个宿主用户执行在首次 provider 调用前创建 scope；记录用户消息 entry ID 为 evidence ref。请求完成、abort、异常分别由宿主推进对应 transition。
  3. provider 调用成功/失败后用现有失败分类器和 snapshot→ref 适配器发布脱敏观测；无可用 provider 时由 scheduler gate 阻止调用，不能先调用再记录。
  4. 分支切换调用 runtime syncBranch；根会话 dispose 释放 runtime。read-only SDK 路径不产生执行 ledger 写入。

验收：第一轮 provider 调用已带 scope；两个并发 session/scope 不串证据；abort 后迟到响应不能复活 scope；dispose 无监听器泄漏。

TaskWire：父子共享 scope 与 contract 驱动调度

  1. 为 ToolSession 增加只读 ExecutionRuntime/固定 scope 访问，不引入全局状态。
  2. 父 task invocation 通过 TaskContractRegistry 注册稳定 contract：contractId/scopeId/taskId/workKey/strategyKey；子 AgentSession 接收固定 executionScopeId。
  3. 子代理不得调用 startScope、syncBranch 或 dispose。完成、失败、abort 映射为 contract 状态和 host observation。
  4. 相同 scope 下重复 work/strategy contract 命中 Watchdog 时复用/拒绝，不重新 spawn；已有运行任务由 TaskManager 结果唤醒，不轮询。

验收：父→子→孙三层 scope 不变；并行兄弟任务 contract 独立；一个兄弟失败不污染另一个；重复任务不增加 spawn 次数。

SanLoopWire：强制 scheduler、Watchdog 与终态治理

  1. runSanLoop 必须接收共享 runtime 或从 executor/session 得到它；删除 scheduler 可选旁路。runId/assignments 创建后立即生成 TaskContract 并设置 runnable nodes。
  2. 每个 commander/worker/supervisor/oracle 调用前执行 scheduler dispatch gate；provider unhealthy 或 contract 不可运行时不消耗 role budget/provider request。
  3. worker 结果转换为 host observation：新文件/测试/receipt 为 evidence；同一错误转换为稳定 failure fingerprint；heartbeat 只更新时间，不算进展。
  4. 处理 Watchdog 动作：duplicate 复用/拒绝；unchanged poll 等待外部事件；diagnose 只运行一次 supervisor 恢复；state drift 同步 runtime 后以 CAS basis 重试。
  5. review 通过仍需 evidence gate 才完成。外部 check 只能由匹配 dependencyId 的 host external receipt 生成 needs_user；turn/token/cost/time/provider-request 限额统一生成 budget_exhausted。
  6. 依赖无法调度但无外部 receipt 时保持内部 blocked/diagnose，不向用户伪报缺权限或缺输入。

验收：现有 solo/team/council/recovery/abort 场景保持；新增 duplicate、provider cooldown、budget_exhausted、external blocker 的事件和终态断言。

8. Work Packets：Wave 3 验证与只读审查

EvidenceLab：确定性故障注入

场景注入必须观察到
认证失败风暴同 provider 连续 auth failure，时间使用注入时钟达到阈值后 cooldown；期间零新增 provider 调用；健康成功复位。
流中断相同 stream failure fingerprint 重复返回首次记录失败，后续被判重复；诊断有硬上限，不循环重派。
无新证据worker 多次返回相同声明、无 host receipt不计 progress；进入 diagnose/等待，最终由宿主终态收口。
重复 work同 scope/workKey/strategyKey 并发注册只 spawn 一次；第二个复用或拒绝，并记录 stable decision。
外部阻塞匹配 check dependencyId 的 host receipt生成 needs_user；仅模型文本声明时不得生成。
预算耗尽turn/token/cost/provider-request 任一触顶budget_exhausted；不再调用 supervisor/provider。
分支与并发两个 scope 并发后切换分支并回放ledger/health/contracts 完全隔离；旧分支晚到事件被拒。
中止清理worker 运行时 abort + disposecontract/scope 终止；订阅释放；晚到结果不改变终态。

测试断言运行行为、entry/receipt/transition 和调用次数；禁止读取实现源码做字符串断言。Dogfood CLI 必须返回非零退出码处理失败 assertion，并输出每个场景的稳定摘要。

ReadOnlyReviewer：独立审查

  • 检查所有终态写入点，证明 model-authored payload 不能直达 completed/needs_user。
  • 检查 runtime/session/task 的 scope 所有权、分支隔离、dispose 顺序和晚到事件。
  • 检查 provider evidence 不含 token、header、raw response、home path。
  • 检查所有 scheduler 可选旁路已删除，所有 role dispatch 都经过 gate。
  • 按严重度输出具体 file:line、可复现场景和修复建议；无问题时明确列出已审查的不变量。

9. Agent 协作协议

  • Main 一次批量派发同一 wave 的所有独立任务；不会“spawn 一个然后空等”。
  • 每个任务都包含 Target / Change / Acceptance，明确非目标和文件所有权；agent 跳过 formatter、lint、全量测试。
  • 公共 API 变更由 owner 先消息通知 Main；Main 广播给依赖者。依赖者不得通过兼容 shim 绕过新契约。
  • 发现需跨所有权修改：停止该文件编辑，向 owner/Main 发送精确 symbol、原因、所需签名；能继续的本地工作继续。
  • 同一波次结束后 Main 收集结果并执行一次接口级检查；失败只重派受影响 slice，不回滚用户或其他 agent 的无关变更。
  • Reviewer 发现 blocker 后，原 owner 优先修复；owner 已释放时 Main 接管。修复后只重跑相关 regression，再进入最终验证。

Wave 2 任务共用 context 模板

# Constraints
- 只修改分配的文件；不得创建第二控制面或兼容 shim。
- Host owns scope/evidence/terminal state；模型文本不能授权完成或 needs_user。
- 使用 Wave 1 已冻结的 ExecutionRuntime API；接口不符先消息 Main。
- 跳过 formatter、lint、项目全量测试；仅运行 assignment 指定的 focused tests。

# Contract
executionScopeId 顶层创建、子代理继承；provider/task 事件进入共享 runtime；
completed 需 host evidence；needs_user 需 typed external blocker；budget 为 budget_exhausted。
