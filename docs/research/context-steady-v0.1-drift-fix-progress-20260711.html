1. 当前结论

核心漂移: v0.1 已实现 TurnDigest、checkpoint、ContextPacket 与 replay 过滤等基础能力，但真实会话暴露出“稳定增长曲线”不等于“上下文窗口长期低于 50%”。当前实现缺少强制 compaction/target budget，也未把大文件、图片、附件、长工具结果从后续上下文中系统性排除。

产品目标需要拆成两个可测合同：一是每轮形成 context-packet 格式的结构化摘要；二是大 payload 不重复进入后续上下文，并在预算压力下触发明确裁剪或压缩，而不是只依赖状态栏百分比自然下降。

3. 修复顺序

  1. 先固化已有 packet 总预算 gate。 这是最小、安全、可测试的一项；若代码已经实现，补测试和文档状态即可。
  2. 修 digest 证据质量。 entryIds、multi-assistant decisions、importance、降级日志都属于摘要可信度，不改变注入架构。
  3. 处理 bulky payload。 从 active context 组装路径解决大文件/图片/附件/长工具输出重复进入上下文的问题。
  4. 设计并实现 append-only delta。 拆 checkpoint 与 per-turn digest delta，避免每轮重写全量 packet。
  5. 最后跑 context-steady focused suite 与 bun check。 验证证据写回本文。

5. 不改口径的风险

  • 如果继续把目标描述为“上下文窗口稳定不超过 50%”，必须新增全局 target budget 与 compaction 触发合同；现有 packet budget 不足以保证该指标。
  • 如果目标是“重复历史不线性增长”，则需要把用户可见文档改成增长曲线/重复 payload 控制，而不是状态栏百分比上限。
  • 真实工具噪音压测已经从 R3 风险变成实证问题；后续测试必须覆盖长工具输出、大文件读取与附件场景。
