2. 阻断性 Findings

P0 · Wire clamp 会删除原文，却只发送被截断的 replacement

maxTokens 被满足了，但 coverage 合同被破坏。

planner.ts:323-354 先以完整 runtime material 生成 coverage，随后才对最终字符串做 prefix clamp；planner.ts:380-402 不会同步撤销 material 或 coverage。结果是 raw user/assistant 已退出 payload，而 digest 的 intent、action 或 decision 可能被截掉。

planMaxTokens = 135
wire tokens   = 135
coverage      = [u1, a1]
raw retained  = false
wire tail     = "userIntent: DIGEST_ ... </san_context_plan>"
action/decision replacement present = false

独立扫描在 cap 132–151 均找到“coverage 有效但 replacement 字段不完整”的区间；cap=1 仍发送 10 tokens，cap=0 记录预算 0 却发送 89 tokens。该行为直接违反 C-04/C-05：replacement 必须原子可见，不能在授权 omission 后再按字符截断。

P0 · Hard-pressure prompt 只进入 journal，没有进入当前 Agent state

同一会话下一轮无法继续被拒绝的任务。

agent-session.ts:8137-8157 在拒绝路径直接调用 session manager append，但没有同步 agent messages 或从 journal 重建 active context。ContextPlan 的 exact audit 只记录 ref，materializer 也不会把 source-index 中缺失的 exact message补回 provider payload。

journal has HARD_REFUSED_MARKER = true
agent state has marker          = false
next prompt provider payload    = false
next follow-up itself present   = true

因此“先持久化当前 prompt，使失败可恢复”的声明只在重启/重载后可能成立；当前进程内直接 follow-up 会丢失被拒 prompt，违背当前任务与规格不可丢失的质量合同。

P1 · Tool-loop re-gate 将完整 context 计算了两次

真实输入仍在 control band，却被误判为 320K hard pressure。

agent-session.ts:8192-8257 的 provider-call refresh 接收到完整 transformed messages；但 agent-session.ts:8388-8396 又拼接 [...this.messages, ...messages]。首请求需要“stored + pending”，tool-loop 则不能再追加一次 stored history。

tool result chars            = 700,000
single tool-result estimate  = 175,000 tokens
steady control max           = 260,000
recorded projected input     = 350,139
burst ceiling                = 320,000
second provider call         = blocked

1.96M 字符的真实超限已能阻止，但当前实现同时会拒绝约 175K 的合法 live tail；这会让正常的大型 grep/read/build 结果过早中断任务。

P1 · 第三轮原始 topic-shift 探针仍失败

只识别显式“new topic”标记，不对普通无关请求做 relevance gate。

planner.ts:115-146 只有 isTopicShiftPrompt() 命中固定短语时才调用 digest/checkpoint relevance。用户自然切换问题但没有写“new topic”时，所有最近 digest 仍被选中。

current prompt       = "compare unrelated language models"
old digest intent    = "legacy security audit"
rebaseReason         = undefined
old digest injected  = true
old raw coverage     = [u1, a1]

这正是第三轮报告使用的输入；新增测试改成了 new topic: ...，没有关闭原回归。它也重新突破了既有 stale-digest 修复原则。

P1 · Semantic required set 会永久保护所有历史 file-touch turn

“当前文件证据”被实现成“任意历史 digest 只要碰过文件就永远 exact”。

agent-session.ts:8027-8072 遍历 active branch 的全部非 fallback digest；只要 filesTouched 非空，就把完整 raw span 放入 required set，没有 relevance、resolved 状态、epoch 或数量上限。

seeded non-fallback file turns = 5
protected refs                 = 11
coverage refs                  = 0
digest materials               = 5
earliest raw turn retained     = true

真实 coding turn 几乎都会触碰文件，因此 raw history 与 digest 会重复累积，最终只能 false burst/hard-pressure，无法证明 12–20 轮 active union 有界。

P1 · Epoch / rebase / checkpoint budget 仍不是完整生命周期
  • agent-session.ts:8011-8015 把当前 leaf 写入 epoch；无 checkpoint 的同主题 3 轮得到 3 个不同 epoch，无法形成 checkpoint 前稳定的 bounded epoch。
  • agent-session.ts:8094-8102 让 checkpoint boundary 优先于 pending topic/resume/budget reason。已有 checkpoint 后显式 topic shift 的 audit 记录为 checkpoint，不是 topic_shift；resume/budget 同样会被覆盖。
  • checkpoint.ts:271-317 的极限裁剪仍没有最终 fail-closed：配置 1–30 tokens 时，独立探针均返回 35-token checkpoint。
  • checkpoint 的 cumulative digest/source refs 仍随轮数增长；当前测试只看 metadata truthy，没有验证 12–20 轮 refs 有界或 resume 等价。
P1 · Branch isolation 没有覆盖 SanLoop 的 plan consumers

Checkpoint 已 branch-safe，但 SanLoop 仍从完整 session tree 取 plan refs。

builtin-registry.ts:145-167 和 agent-session.ts:8582-8587 都向 SanLoop 传 getEntries()。独立分支探针中，off-branch plan 不在 active branch，却出现在 runtime sourceContextPlanRefs；用 getBranch() 构建则为空。

activeBranchHasOffPlan = false
runtime getEntries refs = [offBranchPlanId]
getBranch refs           = []
P2 · 测试与项目规则仍有假阳性
  • agent-session-dogfood.test.ts:94-183 实际跑 8 轮，不是第三轮门槛要求的 20 轮；不覆盖 compaction 或 resume。
  • 同文件 :179 的 ref 断言含 ...some(entry.id === ref) || ref.length > 0，任意非空 dangling ref 都会通过。
  • context-steady/index.ts:11-20 在纯 barrel 使用 named re-export，违反仓库要求的 star-export 约定。
  • 产品级 full-history A/B、真实模型 20-turn p95、burst 恢复与复杂排障质量尚未执行；修复说明对此有正确披露。

5. 第五轮前的硬门槛

  1. Coverage 与 rendered replacement 必须原子绑定：按 material 整体裁减并重新生成 coverage；禁止在 coverage 冻结后切字符串。

  6. 实现稳定 epoch；pending resume/topic/budget reason 优先；checkpoint 超小预算 fail-closed；证明 20 轮 refs/token 有界与 resume 等价。
  7. SanLoop 与所有 plan consumers 只读取 active branch；补 off-branch plan ref 回流测试。
  8. 把 runtime dogfood 扩展到真实 20 turns、large tool loop、status/compaction/resume，并修正 dangling-ref 假阳性断言；之后再做产品 A/B。
